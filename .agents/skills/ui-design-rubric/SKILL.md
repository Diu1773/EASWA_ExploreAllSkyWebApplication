# UI Design Rubric — 버튼·레이아웃 설계 게이트

EASWA는 교육용 전천 웹플랫폼이고, UI의 성패는 "개발자 눈에 멀쩡한가"가 아니라 **학습자(초보·중고생·심화)가 시각적·인지적으로 어떻게 받아들이는가**로 정해진다. 이 스킬은 버튼/레이아웃/패널을 만들거나 고칠 때 **단계별 게이트**를 밟게 해, 흔한 실패(임의색·고아버튼·정보 벽글·중복 패널·코드만 보고 "됐다")를 *설계 단계에서* 막는다.

**기준점:** 사용자가 손수 만든 **Transit Lab**(생각해보기 O/X 자가점검 + 깔끔한 단계 전개 + 일관 토큰)이 품질 바. 새 UI는 거기 톤에 맞춘다.

## 규칙
- 각 단계는 **게이트**다. 통과 못 하면 다음으로 넘어가지 않는다.
- 6단계(런타임 검증)는 **생략 금지** — 코드만 보고 완료를 선언하지 않는다.

## 게이트

### 0. 목적
- 이 요소의 *단 하나*의 일은? 사용자는 누구(초보/중고생/심화)? 흐름 어디에 있나?
- ✅ 한 문장으로 답함 / ❌ "그냥 정보 보여주려고"

### 1. 정보구조 (IA)
- 여기 꼭 있어야 하나? 다른 화면/단계로 보낼 건 없나? 같은 정보가 두 번 나오지 않나?
- ✅ 화면당 결정 1개·핵심만 / ❌ 정보 나열, 자료출처 등 중복 패널, 블럭 밖으로 튕기는 고아 버튼

### 2. 시각 위계 · 토큰
- 색·간격·반경은 **토큰만**: `var(--accent)`(오렌지 ≈#e8722a), `var(--border)`, `var(--text-heading)`, `var(--text-secondary)`, `var(--bg-card)`, `var(--font-mono)`, `var(--radius-lg)`.
- **임의 색 금지** — 특히 시안 `#7dd3fc` 계열은 바이브코딩 표식. 강조는 오렌지 계열로.
- 한 화면에 **primary 액션 1개**. 나머지는 secondary/sm.
- 기존 클래스 재사용: `btn-primary`/`btn-secondary`/`btn-sm`, `inquiry-*` 패널, `transit-step-*` 스텝퍼.
- ✅ 토큰·기존 클래스 사용, primary 하나 / ❌ 하드코딩 색, primary 여러 개, 일회용 스타일 남발

### 3. 상태 · 어포던스
- 정의해야 할 상태: default / hover / active / **disabled / loading / empty / error**.
- 버튼은 **숨기지 말고 보이되**, 못 쓰는 상태면 *왜* 못 쓰는지 알린다(클릭 시 안내). 예: 비로그인 저장 → 버튼 보임 + 클릭 시 "로그인하세요".
- "다음 행동"이 1초 안에 보이나? 죽은 placeholder("연결 대기")는 금지 — 실제 행동(핸드오프/링크)으로.
- ✅ 상태 다 처리, 비활성도 보이고 이유 표시 / ❌ 숨김, 이유 없는 disabled, 죽은 placeholder, 작동 안 하는 버튼

### 4. 인지부하 · 안내
- 정보 패널은 *나열*로 끝내지 말 것 → 한 줄 프레이밍 + **상호작용**(생각해보기 O/X·객관식 자가점검) + 힌트/예시.
- 산출값을 정답으로 던지지 말고 **학습자가 해석**하게(비교·차이설명·기록 힌트).
- 흐름: **정보 → 판단(자가점검) → 기록**.
- ✅ 읽고 판단하게 만듦 / ❌ 벽글, "알아서 읽어", 힌트 0

### 5. 반응형 · 접근성
- 좁은 폭/모바일에서 안 깨짐(겹침·잘림 X). `prefers-reduced-motion` 존중(애니메이션 끔). 키보드 포커스·색 대비 확보.
- ✅ 안 깨지고 모션 끔 존중 / ❌ 좁은 폭 깨짐, 강제 모션

### 6. 런타임 검증 (필수)
- `cd frontend && npm run build` 로 컴파일 확인.
- **프로덕션 서버(5895)** 를 띄워(`.Codex/launch.json`의 `backend`) `preview_snapshot`/`preview_eval`/`preview_screenshot`로 **라이브 확인** — 0~5단계를 실제 화면에서 재점검.
- dev 서버(5173)는 HMR 때문에 screenshot이 멈춘다 → 5895 사용. WebGL 화면(3D·Aladin)은 screenshot 대신 snapshot/eval. 리로드/네비 직후 첫 캡처는 까맣게 나오니 한 번 더. (메모리 `preview_screenshot_prod_server` 참조.)
- ✅ 런타임에서 보고 확인 / ❌ 코드만 보고 "됐다"

## 마무리 (체이닝)
- 변경 후 `/code-review` (버그·재사용·단순화) 실행.
- 학습자 관점 점검은 `/learner-ux-review` (초보·중급·중고생 3 페르소나).

## 가드레일
- 사용자 자산은 **함부로 수정 금지**: Transit Lab(`LabView`/`TransitLab`), `Transit3DScene`, `/tess`. 참고·기준점으로만(명시 요청 시 제외).
- CSS는 `index.css`에 모으고, 인라인 스타일은 동적 위치값에만.
- 트레이드오프는 5개 설계원리(주제중심 / 기술부담완화 / 가시화 / 학습자해석 / 수업적용)로 판단한다.

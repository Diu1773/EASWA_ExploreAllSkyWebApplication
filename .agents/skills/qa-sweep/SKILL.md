# QA Sweep — 전 화면 시각 디테일 자동 점검·수정

사용자가 수동으로 하던 역할(화면 훑기 → 결함 지적 → 수정 확인)을 자동화한다.
**단, 취향·방향 판단은 자동화하지 않는다** — 그건 "판단 필요" 목록으로 모아 보고한다.

## 절차

### 1. 준비
- 서버 확인: `curl http://127.0.0.1:5895/api/health` → 200 아니면 `cd <repo> && python -m uvicorn main:app --port 5895 --app-dir backend` 백그라운드 기동.
- 미반영 변경이 있으면 `cd frontend && npm run build` 먼저 (5895는 dist 서빙).

### 2. 캡처
```
node .Codex/skills/qa-sweep/capture_all.js [출력폴더]
```
- 홈·모듈 인트로·랩 Step 0~6을 1440/1900 두 폭으로 전체 높이 캡처 (기본 출력: OS temp의 easwa_qa_sweep).
- 크롬 프로필(OS temp easwa_qa_profile)에 fit이 저장돼 있으면 Step 5·6이 데이터 채워진 상태로 찍힌다. 비어 있으면 랩에서 분석 풀런 후 재실행 (불러오기→추천 비교성 자동 선택→측광/적합 실행 버튼 순차 클릭 패턴).
- **주의**: 캡처가 길게 늘어지거나 멈추면 networkidle 대기가 원인 — 이 스크립트는 domcontentloaded+폴링만 쓴다. 수정 시에도 유지할 것.

### 3. 검사 (각 캡처를 Read로 직접 보며)
체크리스트:
- **위계**: 소제목이 본문보다 작거나 같음, 킥커·제목·본문 크기 역전, 제목+설명 패턴의 중복 적층
- **여백**: 오른쪽 대규모 빈 영역, 요소가 불필요하게 컨테이너 전폭으로 늘어남 (읽기 폭 860px 기준)
- **정렬**: 카드 높이 불일치, 그리드 어긋남, 기준선 붕괴
- **잘림/겹침**: 텍스트 반토막, 회전 라벨 뭉개짐, 미로드 검은 박스, 요소가 컨테이너 밖으로
- **일관성**: 스텝명(자료 확인/분석 준비)·용어(오염, 식현상 행성)·버튼/킥커 스타일·한글 우선 라벨
- **정직성(원리 3)**: 과장 스케일 미표기, 설명 문구와 시각의 상충, 수치 출처 불명
- 1900 전용 문제는 별도 표기

### 4. 분류와 처리
| 심각도 | 기준 | 처리 |
|---|---|---|
| 상 | 기능 오인 유발(잘림으로 단계 누락 등), 데이터 부정직 | **보고만** — 수정안 제시 |
| 중 | 레이아웃 결함, 큰 빈 영역, 용어 불일치 | **보고만** — 수정안 제시 |
| 하 | CSS·문구 수준 디테일(간격·기준선·라벨 위치·중복 문구) | **자동 수정** |

자동 수정 규칙:
- CSS는 `index.css`에, 문구는 해당 컴포넌트/configs에. **사용자 자산 절대 수정 금지**: `TransitLab`, `Transit3DScene`, `/tess` 페이지, `LightCurvePlot` (문구 오탈자 수준 제외).
- 수정 후 반드시: `npm run build` → 해당 화면 재캡처 → Read로 육안 확인 → 통과 시에만 커밋.
- 커밋: 배치 단위 1커밋, push 후 main ff-merge·push(배포 관행). 수치·데이터 표기는 반드시 백엔드 실값 대조 후 수정(철칙 6).

### 5. 보고
- `docs/QA_DETAIL_SWEEP.md`에 날짜 섹션으로 **누적 기록** (기존 내용 삭제 금지): 발견표(화면/위치/문제/심각도/처리·제안), 자동 수정 내역, 캡처 경로.
- 최종 브리핑: 「한 일(자동 수정 n건) / 발견(상·중 목록+수정안) / 사용자 판단 필요」 — 판단 필요가 0이어도 명시.

## 자율 실행 결합
- 야간: `/goal qa-sweep을 신규 발견 0건까지 반복 (최대 3회)` — 회차마다 4번 규칙 준수, 같은 항목 재발견 시 중단하고 원인 보고.
- 발견 0건 2회 연속이면 "수렴" 선언 후 종료.

## 가드레일
- 검증(재캡처 육안 확인) 없이 "수정 완료" 보고 금지.
- 중·상을 임의로 수정하지 말 것 — 사용자 취향 영역(색·이미지 톤·컴포넌트 구조 변경)은 항상 판단 필요로.
- 스크린샷 산출물(docs/survey/screens)과 PPT는 이 스킬 범위 밖 — 스윕 후 UI가 바뀌었으면 재캡처·동기화 필요를 브리핑에 명시.

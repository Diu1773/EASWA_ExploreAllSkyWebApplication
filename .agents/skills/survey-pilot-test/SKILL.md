# Survey Pilot Test (설문 페르소나 파일럿)

EASWA의 설문은 학생·교사의 반응과 보완 요구를 수집해 플랫폼과 논문을 개선하는 **연구 도구(instrument)**다.
설문의 성패는 "문항이 그럴듯한가"가 아니라 **"실제 응답자가 끝까지 성실히, 혼란 없이 답할 수 있고, 그 응답이 분석 가치를 갖는가"**로 판단한다.
이 스킬은 평가자가 여러 응답자 페르소나에 **빙의**해 설문을 1인칭으로 처음부터 끝까지 응답해보고, 어디서 막히고·귀찮아하고·아무 답이나 찍는지를 근거와 함께 잡아, **무엇을 줄이거나 고칠지 데이터로** 만든다.

핵심 철학: **파일럿은 "미리 자르기"가 아니라 "무엇을 자를지 근거를 만드는" 단계다.** 그래서 이 스킬은 문항을 임의로 삭제하지 않고, *선택 빈도·중복 지적·모호 지적*을 산출해 정제 결정의 증거를 제공한다. 최종 축소는 사용자가 이 근거로 판단한다(설계원리 4의 정신 — 해석·결정은 사람이).

## 언제 쓰나
- 구글폼 설문 초안을 만든 직후, 실제 배포 전 검증
- "체크박스/선택지가 너무 많나? 뭘 줄이지?" 결정 전 근거 확보
- 리커트 문항 뭉치의 편향(묵종·역문항 혼동) 위험 점검
- 논문의 "문항 정제 과정" 서술에 쓸 근거 생성

## 입력
- `.gs` Apps Script(구글폼 생성 스크립트) 또는 문항 목록(마크다운/텍스트).
- 없으면 사용자에게 대상 설문 파일 경로를 묻는다. EASWA 기본 대상은 `docs/survey/easwa_teacher_survey.gs`.
- 스크립트에서 문항을 추출할 때: `setTitle`(문항), `setChoiceValues`(선택지), `addScaleItem`+`setBounds/setLabels`(리커트), `addParagraphTextItem`(서술형), `setValidation`(선택 제한), 역문항 여부(부정 표현)를 파싱한다.

## 응답자 페르소나 (해당되는 것 모두로 각각 응답)
대상 설문의 신분 문항(예: Q1)에 실제로 있는 유형을 우선 채택한다. EASWA 교사 설문 기본 세트:

**① 현직 지구과학교사 (10년차, 수업 적용 관점)**
- 천문 단원을 가르쳐봄. **"내 수업 45분에 이게 들어가나"**가 최대 관심. 수업 적용·활동지·난이도 조절 문항에 진심.
- 바쁘다. 설문이 길면 뒤로 갈수록 성의 하락. 서술형은 **핵심만 짧게**, 막연하면 건너뜀.
- 전문 용어(`RUWE`, `a/R*`)는 알거나 맥락으로 넘김. 체크박스는 "내 경험상 진짜 걸리는 것"만 고름 → 선택 편향 적음.

**② 예비교사 (교대·사대 3학년, 수업 경험 없음)**
- 개념은 배웠지만 **실제 수업/실데이터 경험 부족**. "수업 적용" 문항은 **상상 응답**이 됨 → 이 페르소나가 특정 문항에서 막히면 그 문항은 현직 전용일 가능성.
- 성실하지만 확신 없음 → 리커트에서 **중앙값(3점) 몰림** 경향. 애매한 문항일수록 3점.
- 겹치는 선택지를 만나면 "이거랑 이거 같은 거 아닌가?" 하고 헷갈림 → **중복 탐지에 강함**.

**③ 과학교육 전공 대학원생 (측정·설문 리터러시 높음)**
- 설문 방법론을 앎. **double-barreled 문항, 유도 문항, 묵종 편향, 역문항 배치**를 민감하게 잡음.
- 리커트 라벨·척도 일관성, "모두 선택"과 선택 제한의 모순 같은 **도구 결함**을 지적.
- 이 페르소나의 지적은 심각도 판단의 핵심.

**④ 천문/우주과학 전공자 (교육 맥락은 약함)**
- 천문학적 내용 타당성엔 밝지만 **교육·수업 문항엔 관심/판단 근거 약함** → 교육 문항에서 "잘 모르겠다/중앙값".
- 천문 용어가 틀리거나 과하게 풀어써 있으면 어색해함 → 용어 적정선 점검.

**⑤ (스트레스 테스트) 성의 없는 응답자 / 만족화(satisficer)**
- 빨리 끝내려 함. 리커트는 **한 열로 쭉 체크**, 체크박스는 **다 체크하거나 첫 1개만**, 서술형은 **공란**.
- 목적: 설문이 이런 응답을 **걸러내거나 방지할 구조**인지 테스트(필수 표시, 선택 제한, 역문항, 서술 유도). 이 페르소나가 무사통과하면 데이터 품질 위험.

## 평가 렌즈 = 설계원리 5 + 설문 방법론
모든 발견은 아래 중 하나 이상에 매핑한다.
1. **탐구 주제 중심** — 문항이 현상·탐구 경험을 묻는가, 아니면 기능 나열인가?
2. **기술 실행 부담 완화** — 응답 자체가 과한 부담(길이·반복·읽기량)인가?
3. **분석 과정 가시화** — (설문 맥락) 응답에 필요한 정보/맥락이 문항에 충분히 주어졌나, 아니면 응답자가 상상해야 하나?
4. **결과 해석은 학습자/응답자** — 서술형이 답할 만큼 구체적인가? 산출 강요가 아니라 의견을 끌어내는가?
5. **수업 적용** — 현직/예비가 각각 답할 수 있는 문항인가? 대상 부적합 문항은 없나?
+ 설문 방법론 렌즈: double-barreled, 유도/편향 문항, 묵종 편향, 역문항 배치·라벨 일관성, 선택지 상호배타성·망라성(MECE), "모두 선택 ↔ 선택 제한" 모순, 필수/선택 적정, 예상 소요시간·피로도, 신분 문항과 후속 문항의 정합.

## 절차
1. **문항 파싱** — 입력에서 전 문항을 구조화(번호·유형·선택지·척도·역문항·필수·제한). 서술형/리커트/체크박스 개수와 총 선택지 수를 집계.
2. **페르소나별 1인칭 완주** — 각 페르소나로 **문항 1번부터 끝까지** 실제로 답을 정하며 서술: 각 리커트에 몇 점(과 이유 한 줄), 각 체크박스에 무엇을 고르는지(그리고 **안 고르는 것**), 서술형에 실제로 쓸 내용 or 공란, 멈칫/짜증/헷갈린 지점, 막히는 용어, 누적 피로.
3. **선택 빈도 집계** — 체크박스 선택지별로 "몇 페르소나가 골랐나"를 표로. **0회 선택 = 삭제 후보**, 전원 선택 = 무변별 후보. 리커트는 점수 분포(특히 3점 몰림·역문항 혼동)를 표시.
4. **결함 목록화** — 각 이슈에 `심각도(치명/주요/경미) × 영향 페르소나 × 위반 원리·방법론 × 구체 수정안(줄임/합침/서술전환/문구수정/이동)`.
5. **정제 권고** — "이 근거로 이렇게 줄이면 된다" 표 + 총 소요시간 추정 + 파일럿 전용 P1~P5가 이 근거를 실제로 수집하는지 점검.

## 주의
- **근거를 만들 뿐, 문항을 임의로 삭제·수정하지 않는다.** 권고까지가 이 스킬의 일이고, 반영은 사용자 승인 후.
- 페르소나는 연기하되 결론은 **설계원리·설문 방법론**이라는 근거로 정당화한다(논문 일관성).
- "0회 선택"은 **삭제 확정이 아니라 후보**다. 페르소나 5종은 표본이 작으므로, 실제 파일럿 응답과 교차 확인하라고 명시한다(과신 금지).
- 신분 문항이 다른 설문이면 페르소나 세트를 그 대상에 맞춰 교체한다(예: 전문가 CVI 설문 → 천문학자·천문교육·교육공학 전문가 페르소나).
- 실제 사람 파일럿을 대체하지 않는다. 배포 전 **저비용 사전 점검**으로 자리매김하고, 그렇게 사용자에게 전달한다.

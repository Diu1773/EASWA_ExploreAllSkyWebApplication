## 0. 확정 결정

- 소유자 (2026-08-09): *"zoviz가 준 게 맘에 들어, 나사 웹사이트 같고."*
  → **zoviz 룩이 앱 전체의 디자인 기준이다.** 절제된 무채 기조 + 넓은 여백 +
  큰 제목 위계 + 둥근 카드(12px).
- 이에 따라 2026-08-03 "네모네모(각진 모서리)" 지시는 **폐기**된다. 되돌린
  커밋(`fbd37f3`)의 모서리 0px 는 최종개선에서 부활시키지 않는다.
- zoviz 는 소개 페이지 부품(Hero/Features/Zigzag/Carousel/FAQ/…)만 만들 수
  있고 탐구활동 화면(그래프·표·파라미터·단계 진행)은 못 만든다. 따라서
  **랜딩은 zoviz 산출물을 그대로 쓰고, 탐구활동 TSX 는 아래 "규칙"을 입힌다.**

## 3. 기계적이지 않은 것 — 구현 착수 때 시안 비교로 결정

전역 규약대로 **적용 전 "현재/시안/수정후" 비교 2~3안을 제시하고 승인 후** 반영.

1. **주 강조색(주황 `#e8722a`)의 거취.** zoviz 룩은 무채 + 청/틸이고 주황이
   없다. 후보: (a) 크롬(버튼·포커스·활성 탭)은 무채·청 기조로 바꾸고 주황은
   데이터 하이라이트(적합선 등)로 강등 (b) 주황을 포인트로 유지하되 채도·사용처
   축소. 화면 수백 곳에 걸치므로 실화면 목업으로 판단.
2. **다크 위 주 버튼 형태.** 시안의 라이트 배경 버튼(진한 면+흰 글자)을 다크에
   그대로 두면 사라진다. 후보: (a) 밝은 면(`#e6ebf2`)+진한 글자 — 랜딩 네비
   반전과 같은 방식 (b) 진한 면+흰 28% 테두리 — `landing/zoviz/` 사본이 쓴 방식.
3. **카드 면 처리.** 시안 카드는 투명면+테두리, 앱 카드는 면색(`--bg-card`).
   다크에서 테두리-only 는 위계가 약해질 수 있어 실화면으로 확인.

## 4. zoviz 부품 ↔ 앱 화면 대응

| zoviz 부품 | 앱에서의 자리 |
|---|---|
| Hero / Zigzag / FAQ / ContactForm | **랜딩 전용** (`landing/zoviz/` 그대로) |
| Features 2×2 (아이콘 타일+제목+설명) | 홈 모듈 카드(`ModuleCard`)·For-teachers 안내 블록의 형태 기준 |
| Carousel 카드 (이미지+배지+제목) | 스텝 진행은 기존 `StepNavigator` 유지 — 카드 **형태 규칙**(r12·테두리·20px 패딩·배지)만 적용 |

| 아이콘 타일 (48·r12·틴트) | 모듈 아이콘·패널 헤더 아이콘 |

## 이게 왜 «정본»인가

촬영 시점에 **로컬 `main` · 라이브 배포본 · 현장 전문가 검토가 사용한 빌드(`2956d24`)가
셋 다 일치**한다. 확인 근거:

- `git diff 2956d24..HEAD -- frontend/` → 출력 없음
- 라이브 자산 해시 `index-TIRgC99R.css` · `index-wJBDfKH5.js` — 2026-07-24 기록과 동일
- 병렬 세션 커밋(`6c8f38e` 등)은 `landing/`·`docs/` 만 건드려 앱에 영향 없음

즉 **2026-07-24 현직 교사 12인이 본 화면과 같은 화면**이다.

## 어떻게 찍었나

이 앱은 `#root { height:100vh }` 와 `body { overflow:hidden }` 구조라 문서가
스크롤되지 않고 **내부 컨테이너가 스크롤**된다. 그래서 «창을 길게 해서 찍기»가
통하지 않는다(길게 잡으면 `100vh` 요소가 같이 늘어나 레이아웃이 깨진다).

대신 Chrome DevTools Protocol 로 **내용의 실제 바닥을 잰 뒤 뷰포트 높이를 그 값으로
바꿔서** 찍었다. 이러면 `100vh` 가 곧 전체 콘텐츠 높이가 되어 레이아웃을 유지한 채
전부 담긴다. 스크립트는 세션 스크래치패드의 `capture.py`.

## 담기지 않은 것

Step 1 이후 화면은 **URL 로 바로 갈 수 없다.** `?blockStep=` 을 손으로 넣어도
`InquiryLayout` 이 잠금 상태를 확인해 마지막으로 열린 단계로 되돌린다(정상 동작).
Lab 화면의 단계는 아예 sessionStorage 에만 있어 주소로 지정할 수 없다.

따라서 Step 1~6, 대상 상세, Lab 분석 화면을 담으려면 **실제로 흐름을 진행하며 찍는
방식**이 필요하다. 필요하면 별도로 요청할 것.

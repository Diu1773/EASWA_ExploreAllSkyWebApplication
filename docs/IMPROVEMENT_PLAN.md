# EASWA 개선 계획 (Improvement Plan)

작성 2026-07-20. 현장·동료 피드백 + QA 스윕 발견을 하나로 모은 백로그.
연수(2026-07-22)를 기준으로 **연수 전 / 연수 후 / 공공 배포 전** 3단계로 나눈다.

> 판단 기준은 항상 CLAUDE.md의 5개 설계원리. 각 항목에 원리 번호와 **정직성 노트**(있으면)를 단다.
> 정직성 노트가 달린 항목은 구현 전에 반드시 방침을 합의한다 — 계산식·전처리를 지어내면 철칙(합성·근사 금지)에 걸린다.

## Phase 0 — 연수 전 (D-2, 저비용·고효과만)

큰 개발은 이틀에 무리. 정직성·저비용·즉시효과만 손댄다.

| ID | 항목 | 원리 | 비용 | 상태 |
|----|------|------|------|------|
| P0-1 | **Step 5: 식 깊이 → Rp/R\* 유도 과정 표시** | 3,4 | 낮 | 대기 |
| P0-2 | **Step 5: 공전주기 "계산 안 함" 정직 표기** | 3 | 낮 | 대기 |

- **P0-1**: `depth = (Rp/R*)²` → `Rp/R* = √depth`. 예: `depth 2.105% → √0.02105 = 0.1451`.
  Step 0에 이미 있는 `깊이 ∝ (Rp/R★)²` 공식이 Step 5에서 실제 숫자로 닫힌다.
  fit이 실제로 산출하는 값이라 계산과정 제시가 **정확**하다.
- **P0-2 (정직성)**: 공전주기는 앱이 **계산하지 않는다** — NASA 카탈로그값을 위상접기·fit 입력으로 쓴다.
  근거 3중 확인: ① `period_days`가 `target.get("period_days")`에서 옴 ② fit 자유파라미터는
  Rp/R*·a/R*·경사각뿐, 주기는 고정 ③ Step 5 비교표에서 내측정=문헌 +0.0% 완전일치.
  물리적으로도 단일 TESS sector엔 식이 1회뿐 → 주기는 식 사이 간격이 있어야 나온다.
  → "주기는 알려진 값 사용, 단일 관측으론 못 구하는 이유"를 명시. 계산식 금지.

### P1-1 파이프라인 개념도 — 골격 (합의 필요)

각 단계의 "왜"와 "누가"를 담은 개념도. 단순 순서도 아님. Step 0을 2단으로
(현상 애니 + 파이프라인 개념도).

| 단계 | 왜 하는가 | 주체 배지 |
|------|-----------|-----------|
| 관측 (TESS 위성) | 별빛을 시계열로 기록 | 위성 |
| 계기 보정 (bias·dark·flat·우주선) | 검출기 특성·잡광 제거 | **SPOC 이미 완료** |
| 자료 취득 (MAST→cutout) | 필요한 별 주변만 잘라옴 | 플랫폼 자동 |
| 구경측광 (구경합−배경) | 별빛이 PSF로 퍼짐→다 모아야 진짜 밝기 | 플랫폼 |
| 차등측광 (목표÷비교) | 공통 흔들림 상쇄 | 플랫폼 |
| 정규화·모델적합 (baseline+batman) | 식 깊이·Rp/R* 추출 | 플랫폼 |
| 기준값 비교 (NASA) | 내 측정 검증 | 학습자 |

- **정직성 노트**: TESS cutout은 SPOC가 계기 보정을 **이미 끝낸** 자료다. 학습자·플랫폼이 하는
  "전처리"는 배경 제거(구경측광)·systematics 제거(차등측광)·정규화뿐. 개념도에
  "계기 보정 완료 → 우리는 왜 필요한지만 이해"로 표시해야 정확.
- **원리 2 ↔ 3 균형**: 취득·전처리는 플랫폼이 흡수(원리 2)하는 게 의도. 개념도의 목적은
  "직접 하게"가 아니라 "자동 처리하되 존재·이유를 보이게"(원리 3). 자동 단계는 흐리게,
  학습자 판단 단계(비교성 선택·해석)는 강조.

### P1-2 용어 설명
- `aperture`·`ROI`가 **Step 0 "이 탐구에서 할 일"에서 설명 없이 영어로 첫 등장**. `FWHM`는 Step 3.
- 첫 등장 지점에 hover 정의 또는 괄호 풀이. 3~5개만 절제(툴팁 남발은 과부하 = 원리 3 역효과).

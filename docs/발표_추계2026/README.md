## 제목은 명사구, 요지는 그 아래 한 줄 — 스킬을 그대로 따르지 않았다

스킬이 요구하는 **action title**(요지를 담은 완결 문장)은 영어 관습이다. 그대로 옮겼더니
사장님이 **「AI 티 나는 게 제목절이 영어번역체임」**이라 하셨다. 열두 제목 중 일곱이
「A하지만, B했다」꼴, 둘이 「A가 아니라 B」 부정 대구였다.

한 절로 줄여 봤으나 **「그래도 별로」**였다. 짧게 만들어도 **완결 서술문이라는 게
그대로**였기 때문이다. 「탐구보다 자료 준비가 먼저 온다」는 신문 표제지 발표 제목이
아니고, 「교사 26명이 짚은 것은 해석이었다」는 영어 분열문(It-cleft) 냄새가 난다.

**사장님이 고른 답 — 명사구 제목 + 그 아래 한 줄 요지.** 한국 학회 관례를 지키면서,
「제목만 훑어도 논지가 이어진다」는 스킬의 목적은 요지 줄이 대신 맡는다.

| 제목 (명사구) | 요지 (한 줄) |
|---|---|
| 연구 배경 | 자료는 공개되어 있지만 수업에서 쓰려면 준비 절차가 앞선다 |
| 기존 서비스 분석 | 네 서비스 모두 탐구 흐름은 사용자 몫이었다 |
| EASWA의 구조 | 자료가 다른 세 모듈에 같은 일곱 단계를 적용하였다 |
| 웹 기능 ① 탐구 질문 진입 | 천체명·좌표가 아닌 질문에서 대상과 자료로 이어진다 |
| 웹 기능 ② 분석 조건 설정 | 구경·배경·비교성을 학습자가 정한다 |
| 웹 기능 ③ 기준값 비교와 기록 | 산출값을 카탈로그 값과 나란히 두고 해석을 남긴다 |
| 개발 방식과 검증 | AI가 쓴 코드는 실행되어도 값이 틀릴 수 있다 |
| WASP-121 b 처리 조건별 결과 | -12.8%가 -2.8%까지 좁혀졌다 |
| 점검의 한계 | 남은 -2.8%와 비교성의 효과는 나누지 못했다 |
| 사용자 검토 결과 | 실행 부담은 낮고 기준값 해석이 최하위였다 |
| 보완 요구 | 용어·그래프 해석과 수업용 자료에 몰렸다 |
| 결론 | 조건을 드러내야 차이를 설명하는 활동이 성립한다 |

본문에서도 「~것과 ~것은」 명사화 여섯 곳을 고쳤다.

## 문체는 개조식이다

사장님 지시 — *「~다 말고, 음, ~했음 않음 이 말투로」*. 한국 발표자료·보고서의
표준 문체다. **서술어를 명사형 어미(-(으)ㅁ)로 닫고, 두 절은 마침표나 줄표로 끊는다.**
요지 줄과 본문 마흔네 곳을 바꿨다(`to_gaejo.py`).

| 전 | 후 |
|---|---|
| 자료는 이미 충분하다. | 자료는 이미 충분함 |
| 네 곳 모두 … 두지 않았다. | 네 곳 모두 … 서비스 밖에 있음 |
| 설치도 로그인도 없다. 브라우저에서 바로 열린다. | 설치·로그인 없이 브라우저에서 바로 열림 |
| 화면이 돌아간다고 값을 믿을 수는 없다. | 화면이 돌아간다고 값을 믿을 수 없음 |
| 실행을 돕는 일과 해석을 돕는 일은 다른 과제다. | … 다른 과제임 |

**본문을 고칠 때 이 문체를 깨지 않는다.** `build.py` 안에서 「~다」로 끝나는 문장이
보이면 주석이나 파일 머리글이지 슬라이드 글이 아니다.

## 화면 캡처는 잘라 쓴다

## 목차는 일곱 묶음이다

사장님 지시 — *「목차도 만들자」*. 열일곱 장을 일곱 묶음으로 접었다.

연구 배경 · 기존 웹 환경 · EASWA가 가야 할 방향 · 개발 방식 ·
EASWA의 구조와 웹 기능 · 사용자 검토 결과 · 후속 과제와 결론

**쪽 번호는 목차에 적지 않았다.** 장을 더 넣거나 빼면 목차의 숫자도 같이 고쳐야 하는데,
지금처럼 자주 바뀌는 동안에는 어긋나기 쉽다. 머리말 옆 쪽 번호는 `build.py` 끝의
runner 가 실제 장 수를 세어 매기므로 저절로 맞는다.

## 교육 지향 환경은 «분석하지 않았다» — 그래서 단정하지 않는다

사장님 지적 — *「교육지향환경에서 근데 뭐가 문제였고 그런걸 어떻게 하지 분석을
안했는데.. ㅋㅋ」*. **맞다.** 논문 3.2 는 이렇게 적었다.

> 특정 학습 활동을 미리 담아 둔 교육 지향 환경(1.2)은 학교 탐구 흐름을 이미 갖추고
> 있어 이 분석에서 제외하였다.

사례분석(표 2·3)의 대상은 자료 제공 서비스 넷뿐이다. 그러니 두 장을 다르게 쓴다.

| | 예시 ① 자료 제공 서비스 | 예시 ② 교육 지향 환경 |
|---|---|---|
| 근거 | **워크스루로 분석한 결과** (표 3) | 화면과 안내문에서 «본 것» |
| 부제 | 천체명·좌표·카탈로그에서 시작 | **「사례분석 대상이 아님 — 두 곳의 화면과 안내문에서 확인한 것만 적음」** |
| 셋째 줄 | → 탐구 질문에서 출발하는 진입 경로가 없고… | → 대상이 정해져 있고, **안내문이** Excel 이 필요하다고 **밝힘** · 탐구활동이 분류에 머묾 |
| 말투 | 판정 | **관찰 — 「밝힘」·「없음」처럼 화면에서 읽히는 것만** |

출처 줄에도 「이 두 곳은 학교 탐구 흐름을 이미 갖추고 있어 논문의 사례분석에서는
제외하였음(3.2)」을 적어 두었다. **발표에서 「저쪽은 이게 문제다」라고 말하지 않는다.**

것이 된다.

### 두 방식을 나란히 놓은 리뷰 — 사장님이 주신 링크의 «원문»

사장님이 themoonlight.io 의 한국어 요약 링크를 주시며 *「이미 논문이 있나본데??」*
하셨다. **요약본은 인용하지 않았다.** arXiv 원문을 열어 저자·제출일·초록·표 1·본문
비유까지 확인하고 원문만 인용한다.

> Sapkota, R., Roumeliotis, K. I., and Karkee, M. (2025)
> *Vibe Coding vs. Agentic Coding: Fundamentals and Practical Implications of Agentic AI*
> arXiv:2505.19443 (2025-05-26 제출, 버전 하나)

10장 표는 그 논문 표 1(Table I)의 네 항목을 우리말로 간추린 것이다. 확인한 원문 표현 —

| 항목 | Vibe | Agentic |
|---|---|---|
| AI Autonomy Level | Low to Moderate | Moderate to High |
| Developer's Primary Role | Director, Co-Pilot, Prompter | Architect, Project Manager, Supervisor |
| Interaction Model | highly conversational iterative cycles | Goal delegation and monitoring |
| Planning & Task Decomposition | Primarily human-led | Primarily AI-led within defined constraints |

본문의 비유도 그대로 옮겼다 — vibe 는 `high-speed copilot`, agentic 은
`an intelligent collaborator capable of independently steering the aircraft`.

**사장님 메모의 「쉬지 않고 일하는」은 넣지 않았다.** 원문에서 그 서술을 찾지 못했다.
쉬지 않는다는 것은 확인할 수 없는 말이고, 표 1 의 항목만으로도 하려는 말이 선다.

### 그림을 옮겨 쓰기 전에 라이선스를 먼저 본다

| 전 | 후 |
|---|---|
| 탐구보다 자료 준비가 먼저 옴 | 탐구를 시작하기도 전에 자료 준비부터 해야 함 |
| 이 연구가 잡은 자리 — 플랫폼이 준비 절차를 맡고… | 그래서 준비 절차는 EASWA 가 맡고… |

PDF 원문에서 「그 자리에」·「잡은 자리」·「먼저 옴」·「도메인」을 다시 훑어 남은 것이
없음을 확인했다.

## 도식이 슬라이드 폭을 못 채운 이유 — 출처 줄을 «축»에 붙였다

`ax.text(..., transform=fig.transFigure)` 로 출처를 적으면 그 글자는 **축의 자식**이라
`tight_layout` 이 축 안에 넣으려고 축을 오른쪽·위로 민다. 그림 자체는 멀쩡한데
본체가 폭의 13.7% 자리에서 시작했다. **`fig.text()` 로 바꾸니 2.4% 로 돌아왔다.**
`figs_v10.py` 의 `fig_scale` 은 원래 `fig.text` 를 써서 이 함정에 걸리지 않았다.

판별법 — 그림 파일의 잉크 범위를 재면 된다. 전체는 1.1%~97.8% 인데 상자 띠만 재면
13.7%~97.8% 이면 축이 밀린 것이다.

### 겹침도 같은 뿌리였다

사장님 지적 — *「각 칸끼리?표끼리?겹치잖아」*. 칸 사이 간격이 **`pad` 의 두 배보다
좁으면** 옆 칸의 확장분과 서로 먹고 들어가 한 덩어리로 보인다. 자료 규모 도식은
가로 간격 0.022 에 pad 0.012 × 2 = 0.024 였고, 세로도 줄 사이가 0.004 모자랐다.
막힌 경로 도식은 간격 0.014 로 더 좁아 다섯 칸이 붙어 한 줄처럼 보였다.

### 왜 못 찾았나 — PNG 는 멀쩡했다

파일의 흰 여백만 재면 **내용이 가장자리에 닿지 않는다.** 실제로 잘린 곳은 **축(axes)** 이다.
`FancyBboxPatch` 는 `boxstyle="round,pad=…"` 만큼 **바깥으로 더 커지는데**, 그 확장분이
축의 0~1 밖으로 나가면 matplotlib 이 **테두리만 조용히 잘라** 낸다. 칠은 남고 선이
사라지니 「열린 상자」로 보인다. 여백을 재는 검사로는 안 잡힌다.

### 그래서 `box()` 가 스스로 검사한다

```python
PAD = 0.004                      # 간격보다 작게 잡는다
assert 0 <= x - PAD and x + w + PAD <= 1        # 축 밖으로 나가나
for 이미 그린 상자: assert 겹치지 않나           # 옆 칸과 먹고 들어가나
```

좌표를 잘못 잡으면 그림이 만들어지지 않고 **그 자리에서 멈춘다.** 일부러 겹치게 넣어
검사가 실제로 걸리는 것까지 확인했다. **눈으로 찾지 않는다.**

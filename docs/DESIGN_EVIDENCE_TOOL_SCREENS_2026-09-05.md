# 탐구활동 화면 — 근거 조사

2026-09-05. 소유자 지시 — *"일단 이런 탐구활동 류에서 디자인이 또 있을거아니야?
커뮤니티 전공자들 의견먼저 조사하고 하네스짜고 그렇게 하자 그렇게 해야 잘되네"*.

랜딩 때와 같은 순서로 간다. **조사 → 하네스 → 만들기.** 이 문서는 첫 단계다.

---

## 0. 먼저 나온 결론

**도구 화면의 정보 밀도는 커뮤니티 의견으로 못 정한다. 합의가 없다.**
「한 화면에 너무 많다」 7.5% 와 「전문가는 밀도를 원한다」 7.2% 가 거의 같은 크기로 맞선다.

그래서 밀도는 **대상이 정한다.** EASWA 의 대상은 중고등학생과 예비교사, 즉 초보다.
초보 쪽에는 잰 값이 있다 — 아래 §1.

그리고 도구 화면에는 랜딩에 없던 규칙이 따로 있다. **개요 먼저, 되돌리기, 값 꺼내기**
(§2). 이건 취향이 아니라 30년 된 표준이고, EASWA 에 빠진 것이 있다.

## 1. 학습 쪽 — 설명을 어디에 두느냐가 가장 크다

### Mayer 다중매체 학습 메타분석 (2025)

> A meta-analysis of Richard Mayer's multimedia learning research: Searching for
> boundary conditions of design principles across multiple media types.
> *Educational Research Review* (2025).
> 92편 논문 · 181개 연구 · **591개 효과크기**.

| 원리 | 효과크기 g |
|---|---|
| **인접성 — 관련된 글과 그림을 가까이 둔다** | **0.74** (가장 큼) |
| 그림+글을 함께 쓴다 | 0.39 |
| 신호 주기 — 어디를 볼지 표시한다 | 0.38 |
| 전체 평균 | 0.37 |

**가장 큰 효과가 「글과 그림을 붙여 놓기」다.** 광도곡선을 왼쪽에 두고 그 설명·질문을
오른쪽 별도 패널에 두면, 학습자는 둘을 눈으로 왕복하며 작업기억을 쓴다. 이걸
분리주의(split attention) 라 부르고, 메타분석에서 가장 큰 손해 항목이다.

### 이미 확보해 둔 것 (2026-09-04 조사)

- **Quintana 외 (2004)** — 과학탐구 소프트웨어 비계 설계 프레임 7지침·18전략.
  도구 화면에 직접 걸리는 것은 셋이다.
  - 지침 **4** 복잡한 과제에 구조를 준다 — 4a 경계 설정 · 4b 과제 분해 · **4c 기능 모드로
    활동 공간을 제한**
  - 지침 **6** 눈에 안 띄는 반복 작업은 자동 처리 — 6a 인지 부담 감소 · **6b 산출물 정리** ·
    **6c 도구 간 이동**
  - 지침 **7** 탐구 중 표현과 성찰 — 7a 계획 · 7b 점검 · 7c 의미 만들기 중 표현
- **Skarlatidou 외 (2019)** JCOM 18(01) A02, 844건→62편 종합 —
  버튼을 크게 · **튜토리얼은 건너뛰고 나중에 다시 열 수 있게** · 제출 확인을 줄 것
- **Zooniverse 베타 설문** (약 10만 명 발송 · 약 1,200명 응답) 최다 불만 —
  막혔을 때 어디로 갈지 모름 · **과제 뒤 다음 단계 불명확** · 스크롤이 많음 ·
  단축키 없음 · **이전 분류를 보고 싶음** · 이미지를 더 크게 보고 싶음

## 2. 정보시각화 쪽 — 30년 된 표준

> Shneiderman, B. (1996). The Eyes Have It: A Task by Data Type Taxonomy for
> Information Visualizations. *IEEE Symposium on Visual Languages*, 336–343.
> 전문 사본: `docs/design_audit/tool_ui_2026-09-05/shneiderman1996.txt`

**개요 먼저, 확대하고 거르고, 필요할 때 세부.** 그리고 일곱 과제를 정의한다.

| 과제 | 원문 정의 | EASWA 에 있나 |
|---|---|---|
| Overview | 전체를 한눈에 본다 | 있음 (전천 지도·전체 광도곡선) |
| Zoom | 관심 항목을 확대 | 있음 |
| Filter | 관심 없는 것을 걸러낸다 | 부분 (섹터 선택) |
| Details-on-demand | 항목을 골라 필요할 때 세부를 본다 | 있음 |
| Relate | 항목 사이 관계를 본다 | 있음 (측정값↔기준값) |
| **History** | **되돌리기·재생·점진적 다듬기를 위해 조작 이력을 남긴다** | **확인 필요 — 없어 보인다** |
| **Extract** | **부분집합과 질의 파라미터를 꺼낼 수 있게 한다** | 부분 (기록은 있으나 분석 조건을 값으로 꺼내는지 확인 필요) |

**History 가 특히 걸린다.** 학습자가 구경·관심영역·섹터를 바꿔가며 시도하는 화면인데
「방금 전 설정으로 되돌리기」가 없으면, 잘못 건드린 뒤 처음부터 다시 해야 한다.
Zooniverse 설문의 「이전 분류를 보고 싶다」와 같은 요구다.

## 3. 커뮤니티 — 두 진영이 팽팽하다

Hacker News 공개 검색 API. 대시보드·마법사·제어판·플롯 UI 계열 낱말로 모았다.
스크립트 `docs/design_audit/community_2026-09-04/gather_tool_ui.py`.

- 수집 1,934건 → **도구 UI 관련 1,731건**
- 연도 2007~2026. **2023~2026 이 741건**으로 최근이 절반 가까이다

| 무엇을 말하나 | 건수 | 비율 |
|---|---|---|
| **한 화면에 너무 많다** (과밀·정보 과부하) | 130 | **7.5%** |
| **전문가는 밀도를 원한다** (여백은 낭비) | 125 | **7.2%** |
| 단계로 쪼개라 · 마법사 · 점진적 공개 | 82 | 4.7% |
| 숨기지 말고 보여라 (메뉴에 파묻힘) | 14 | 0.8% |
| 되돌리기·실수 복구 | 13 | 0.8% |
| 지금 뭐가 일어나는지 (진행 표시·먹통) | 12 | 0.7% |
| 기본값이 중요하다 | 3 | 0.2% |

**읽는 법.** 이 표본은 해당 낱말로 골라 뽑은 것이라 비율이 일반 발생률은 아니다.
쓸 수 있는 것은 **상위 두 항목이 거의 같은 크기라는 사실**이다. 랜딩 조사(shadcn 8.3% 대
그라디언트 2.8%)처럼 한쪽으로 기울지 않는다. 도구 화면의 밀도는 커뮤니티가 정해 주지 않는다.

세 번째 항목 「단계로 쪼개라」 4.7% 는 EASWA 가 이미 하고 있는 것(Step 0–6)을 지지한다.

## 4. 실제 도구는 어떻게 생겼나

세 곳을 헤드리스로 열어 캡처했다. `docs/design_audit/tool_ui_2026-09-05/`.

**NASA Exoplanet Archive (표)** — 밝은 바탕, 극도로 조밀한 표. 위에 「Select Columns ·
Download Table · Plot Table · View Documentation · User Preferences」, 아래에 「Clear
Checked · Check All · Reset Filters」. **모든 동작이 이름 붙은 버튼이고 숨긴 메뉴가 없다.**
「Showing records 1 to 27 of 40144」처럼 현재 위치를 숫자로 말한다.

**SDSS SkyServer Navigate** — 좌측 제어 레일(Find by Name · Image Options · Drawing
Options · Advanced Options 가 **접히는 그룹이되 제목은 보임**) + 중앙 하늘 이미지 +
우측 세부 패널(RA·dec·type·u·g·r·i·z 를 **값 표로** 나열하고 그 아래 Quick Look ·
Explore · Recenter · Add to notes 동작 링크). **EASWA 의 좌 흐름 + 중앙 작업 + 우 결과와
같은 뼈대다.** 여기서 배울 것은 배치가 아니라 **세부 패널이 값을 표로 세우고 동작을
그 아래 붙였다**는 점이다.

**Zooniverse (Galaxy Zoo)** — 주 선택은 큰 채운 버튼 두 개. 그 아래 「내 통계」와
「최근 분류」 패널.

## 5. EASWA 실측 — 지금 어떤 상태인가

빌드 후 `localhost:5895`, 1440×900 에서 잰 값이다. 대상은 외계행성 탐구블럭 Step 0.

| 항목 | 실측 | 판단 |
|---|---|---|
| 큰 블록 수 | **12개** | 하네스 §3 은 2~6개. 두 배다 |
| 가장 큰 그림(시뮬레이션 캔버스) | 918×516 = 화면의 **36.5%** | Step 0 은 소개라 이 값 자체는 문제 아님. 분석 단계에서 다시 재야 함 |
| 보이는 버튼·링크 | 15개 중 **11개가 면을 채움** | **버튼감은 홈보다 낫다.** §3-1 위반은 여기선 작다 |
| 테두리 있는 요소 | 41개 | 경계는 충분히 그어져 있다 |
| `document.body.scrollHeight` | **900 = 화면 높이** | 내부 스크롤 컨테이너다. 더 있는지 밖에서 안 보일 수 있음 |
| 아이콘 | 일시정지를 **`❚❚` 문자 글리프**로 씀 | 이모지는 아니지만 아이콘도 아니다 |
| 버튼 라벨 | `← 이전 단계`, `← 홈` | 화살표 접두. 홈에서 지적된 것과 같은 항목 |
| **단계 이동** | **된다.** `?target=wasp_6_b&blockStep=step4_run_visualize` 로 4단계가 그대로 열린다 | 아래 정정 참조 |

### 정정 — 「URL 로 단계를 못 연다」는 내 오진이었다 (2026-09-05)

처음에 *"`?blockStep=4` 로도 안 열린다"* 고 적었다. **열린다.** 내가 두 가지를 틀렸다.

1. `?blockStep=` 는 숫자가 아니라 **단계 id** 를 받는다 — `step0_intro` · `step1_select` ·
   `step2_metadata` · `step3_analysis_conditions` · `step4_run_visualize` · `step5_compare` ·
   `step6_reflect`. `4` 는 유효하지 않아 0단계로 떨어진다.
2. 선택 단계 뒤로 가려면 **`?target=` 이 함께 있어야 한다.** `ExoplanetModuleView` 의
   `selectionConfirm.ready = Boolean(targetId)` 가 그 문이고, 2026-07-18 회귀
   (「초안 계속하기 눌렀는데 step1 로」)를 막으려고 일부러 넣은 것이다.

사본에서 확인한 결과 — `?target=wasp_6_b&blockStep=step2_metadata` 와
`…&blockStep=step4_run_visualize` 둘 다 정상으로 열린다.
**따라서 「교사·시연용 우회로가 필요하다」는 과제는 없어진다.** 자동 캡처도 막혀 있지 않다.
기록은 `Main/FAILURES.md`.

남는 잠금은 하나뿐이다 — **5·6단계는 적합 결과가 있어야 열린다**
(`maxUnlockedStepIndex={fit ? undefined : 4}`). 검토용으로는 사본에 `?unlock=1` 분기를
두었고 main 에는 넣지 않는다.

### 남아 있는 잠금은 설계다

5·6단계가 적합 결과를 요구하는 것은 Quintana 지침 **4a**(경계를 설정해 복잡한 과제를
제한한다)와 **4c**(기능 모드로 활동 공간을 제한한다)에 해당한다. **그대로 둔다.**

검토·자동 캡처는 `?target=<id>&blockStep=<단계 id>` 로 4단계까지 되고, 5·6단계는
사본에서 실제로 적합을 돌리거나 `?unlock=1`(사본 전용)로 연다. 앱에 우회로를 넣을 이유는 없다.

## 6. 이 조사가 하네스에 남길 것

다음 다섯 줄로 `DESIGN_HARNESS_EASWA.md` §4-1 을 쓴다.

1. **설명은 그림 옆에 둔다.** 광도곡선과 그 설명·질문을 다른 패널로 떼지 않는다.
   (인접성 g=0.74 — 다중매체 원리 중 가장 큰 효과)
2. **밀도는 대상으로 정한다.** 커뮤니티는 갈렸다. EASWA 는 초보 대상이므로
   한 화면에 큰 덩어리 2~6개, 지금은 12개다.
3. **되돌리기와 이력을 넣는다.** Shneiderman 일곱 과제의 History 가 빠져 있다.
4. **분석 조건을 값으로 꺼낼 수 있게 한다.** Extract. 기록에 조건이 남는지 확인한다.
5. **동작은 이름 붙은 버튼으로.** 문자 글리프(`❚❚`)·화살표 접두를 쓰지 않는다.
   NASA Archive 가 40,144행짜리 표에서도 그렇게 한다.

### Step 4(분석·시각화) 실측 — 사본에서 채웠다

`?target=wasp_6_b&blockStep=step4_run_visualize`, 1440×900 첫 화면 기준.

| 항목 | 실측 | 판단 |
|---|---|---|
| 큰 블록 수 | **16개** | Step 0 의 12개보다 많다. 하네스는 2~6 |
| 첫 화면의 그림 | **0개** (8,000px² 넘는 canvas·svg·img 없음) | **분석 단계인데 첫 화면에 자료가 없다** |
| 버튼·링크 | 19개 중 **15개가 면을 채움** | 버튼감은 문제 아님 |
| 글리프 라벨 | `← 홈` 하나 | 홈 화살표와 같은 항목 |

**가장 큰 것은 두 번째 줄이다.** 학습자가 분석 단계에 도착했을 때 첫 화면은 전부 제어와
글이고, 자료는 「불러오기」를 누른 뒤에야 나타난다. Shneiderman 의 **개요 먼저**와
정반대다. §6 의 규칙 1·2 가 겨냥하는 지점이 여기다.

미해결로 남기는 것 — **5단계(기준값 비교) 실측.** 적합 결과가 있어야 열려서
사본에서 실제로 적합을 돌린 뒤에 재야 한다.

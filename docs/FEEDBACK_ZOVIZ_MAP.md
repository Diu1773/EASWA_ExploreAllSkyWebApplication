# 교사 피드백 → zoviz 설계 결합 지도

> 작성 2026-08-09. 원자료: `docs/survey/RESULTS_2026-07-24_교사시연.md` (N=12 설문
> + 앱 로그 18명). 시안: `landing/zoviz/` + `docs/ZOVIZ_DESIGN_MIGRATION.md`.
> 목적: 최종개선에서 "디자인 갈아입히기"와 "피드백 반영"이 따로 놀지 않도록,
> 피드백 항목마다 zoviz 체계 안의 정확한 자리를 지정한다.

## 0. 결합 원칙 3개

1. **시안에는 이미 피드백의 그릇이 있다 — 내용물만 가짜다.** zoviz 시안의
   For-teachers 4카드(수업시간·그룹·난이도·선수지식)는 교사 장벽 상위 3개
   (수준 재구성 10명·시간 8명·선수개념)와 구조가 1:1인데, 지금 든 텍스트는
   zoviz가 지어낸 것이다. **시연 실측과 교사 실답변으로 교체**하는 것이
   결합의 절반이다.
2. **zoviz 부품이 피드백 해결 장치로 재사용된다.** 배지(11px 대문자 틴트 알약)
   → 용어 칩, 아이콘 타일+항목 제목 → "이 단계에서 할 일" 블록, 카드 규칙
   → 그래프 축 설명 캡션. 새 부품을 발명할 필요가 거의 없다.
3. **디자인이 못 푸는 피드백을 섞지 않는다.** 동시접속 성능·교육과정 불일치는
   화면을 바꿔도 안 풀린다 — 문서와 운영으로 분리한다(§4).

## 2. 랜딩(zoviz 산출물)에 지금이라도 넣을 수 있는 실측

랜딩은 배포 밖 정적 파일이라 앱 동결과 무관하다. 시안의 지어낸 숫자를 실측으로
바꾸는 것은 언제든 가능:

| 시안 자리 | 지금 내용 (zoviz 창작) | 교체할 실측 |
|---|---|---|
| For-teachers "Suggested time" | "45–60 minutes" | 교사 수행 10~30분(Q7-1 9/12명) · 학생 권장 2차시 또는 동아리(Q21-2) |
| For-teachers "Difficulty level" | "Middle to early undergraduate" | 심화·동아리·진로집중반 우선(서술 8·9·12), 기본 교육과정 적용은 한계 명시 |
| For-teachers "Prerequisites" | "basic light-curve concepts" | 식현상·차등측광 선행 설명 필요(Q20 서술 9·12) — 교사 자료 링크 |
| Carousel Step 카드 설명 | 일반론 | 각 스텝의 실제 목적 + 어려움 큰 단계(비교·해석)에는 지원 장치 예고 |
| (신설 후보) Stats 띠 | 없음 | 시연 실측: 참여 18명 · 자기진단 정답률 97% · Rp/R\* 중앙값-문헌 차 0.0003 — zoviz 부품 목록에 Stats 가 있어 시스템 안에서 가능. **신설이므로 시안 비교 승인 대상** |

## 3. 교사용 자료(앱 밖 문서)가 받는 것

F1의 본체. 차시안 2종(2차시 탐구형 / 동아리·과제연구형 — Q21-2 분포 그대로),
선수개념 미니 자료(식현상·차등측광 — Q20 서술 9·12), 인쇄용 용어표(F2와 동일

대한 정직한 대응 — 되는 단원과 안 되는 단원을 표로 밝힌다.

## 4. 디자인이 못 푸는 것 (섞지 말 것)

- **동시접속 성능** (서술 10, Q21 1명) — 서버 용량 문제. 현재 결정: 무료 플랜
  유지 + 시연 전 수동 깨우기(TRACK 2026-08-08). 상용/확장 시점의 과제로 이관.
- **교육과정 정합·선택자 감소** (서술 3·8·11) — 제도 요인. 화면이 아니라 §3
  성취기준 매핑과 논문 논의(§5.4~5.5)가 받는다.
- **크롬북 사양** (서술 7) — 최종개선 검증 항목에 "저사양 브라우저 확인" 한 줄로.

## 5. 우선순위 (데이터가 정한 순서)

1. **Step 5 기준값 비교(F3) + Step 6 기록(F4)** — 측정 최저점 + 보완요구 1위 +
   학생 어려움 1·2위가 전부 여기 겹친다. 최종개선에서 가장 공들일 화면.
2. **용어 칩(F2)** — 장벽 2위(9명)이고 저비용 반복 적용이라 효과/비용비 최고.
3. **스텝 할 일 블록(F6) + 자기진단 승격(F7)** — 서술 11·12가 지목한 가시성.
4. **랜딩 실측 교체(§2)** — 앱 동결과 무관하게 선행 가능.
5. **토큰 이식(F8=스펙 §2)** — 위 작업의 바탕색. 실제로는 1~3과 한 패스.

유지할 것(피드백이 칭찬한 것, 건드리지 말 것): 코딩 없는 분석(Q9 4.50),
해석 지원(Q14 4.50), 출처 확인(Q10 4.42), 직접 조작(Q11 4.42, 서술 10),
화면 구성·인터페이스·자료 활용(서술 1 "가장 잘 되어 있는 점").

## 6. 논문이 이미 그어놓은 선 — 스캐폴딩의 한계 (§2.3)

> 2026-08-09 추가. 논문 §2.3 을 읽고 §1 의 F3·F4 를 수정했다.
> **초안의 "차이 원인 후보 체크리스트"는 논문의 자기 설계 원리를 위반했다.**

논문 §2.3 은 자동화를 세 열로 나누고, 결론 §6.1 둘째가 이를 다섯 설계 원리
중 하나("결과 해석의 학습자 수행")로 못박는다.

| 플랫폼이 **자동화** | 플랫폼이 **가시화**(학습자가 확인) | **학습자가 직접 수행** |
|---|---|---|
| Python 설치, API 호출, 파일 처리, 서버 계산, 자료 다운로드, 반복 계산 | 데이터 출처, 시간축·밝기값의 의미, 전처리 과정, 분석 조건, 모델 가정 | 그래프 패턴 해석, **기준값과의 차이 설명**, 산출값 의미 해석, 과학적 정당화 |

「기준값과의 차이 설명」이 셋째 열에 있다. 원인 4종을 선택지로 미리 주면
플랫폼이 셋째 열의 일을 대신하는 것이고, 논문이 경고한 실패 모드
("최종 산출값만 제시 → 학습자가 근거를 이해하지 못한 채 결과 수용")를
선택지 형태로 재현하게 된다. 교사 서술 9번의 "버튼만 누르는 주입식" 우려와
같은 지점이다.

**따라서 보완 요구(도움말 7명·기록 강화 7명)는 둘째 열을 두껍게 해서 받는다.**
무엇을 해석해야 할지 막막하다는 Q15 저점은, 답을 주는 것이 아니라 *판단에
필요한 수치를 눈앞에 놓는 것*으로 푼다.

### 단서를 줄여가는 설계(fading)

논문 §2.3 은 이미 이름을 갖고 있다 — "학습자의 숙련에 따라 단서를 점진적으로
줄이는 단계적 스캐폴딩 소거(fading)". 안내를 늘릴지 줄일지의 문제가 아니라,
**언제 거두는지**를 설계하는 문제다. 최소 구현: 학습자가 자기 설명을 제출한
뒤에 비교용 예시가 열린다(먼저 열리지 않는다).

### 탐구 수준 좌표 (Banchi & Bell, 2008)

논문은 EASWA 가 **구조화형→안내형**을 지향한다고 명시했다. 교사 서술 8번의
"쉬운 자료 해석부터 순차적으로"는 그 아래 칸인 **확인형**을 요청한 것이다
(결과를 이미 아는 자료로 해석만 연습). 이는 §6.2 제언 다섯째의 "난이도 조절"에
자리가 있으므로, 최종개선의 필수가 아니라 **후속 모듈 과제**로 둔다.

### 사용 맥락은 하나로 좁히지 않는다

§5.4 는 1차 조사에서 동아리·과제연구가 더 많이 선택된 것을 **실패가 아니라
구분해야 할 사실**로 적었다 — "플랫폼의 교육적 가치에 대한 인정과 정규
교육과정으로의 편입 가능성은 구분하여 볼 필요가 있으며". §6.2 제언 다섯째도
지구과학 수업·탐구활동·동아리·예비교사 교육·교사연수를 나란히 둔다.
따라서 최종개선은 **정규수업용/동아리용 중 하나를 고르지 않는다.** 현재의
깊이를 유지하되, 정규 차시 편입을 화면으로 주장하지 않고 교사용 자료(§3)와
논문 논의가 받는다.

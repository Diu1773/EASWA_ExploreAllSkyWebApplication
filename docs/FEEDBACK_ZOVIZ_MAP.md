# 교사 피드백 → zoviz 설계 결합 지도

> 작성 2026-08-09. 원자료: `docs/survey/RESULTS_2026-07-24_교사시연.md` (N=12 설문
> + 앱 로그 18명). 시안: `landing/zoviz/` + `docs/ZOVIZ_DESIGN_MIGRATION.md`.
> 목적: 최종개선에서 "디자인 갈아입히기"와 "피드백 반영"이 따로 놀지 않도록,
> 피드백 항목마다 zoviz 체계 안의 정확한 자리를 지정한다.

## 0. 결합 원칙 3개

1. **시안에는 이미 피드백의 그릇이 있다 — 내용물만 가짜다.** zoviz 시안의
   For-teachers 4카드(수업시간·그룹·난이도·선수지식)는 교사 장벽 상위 3개
   (수준 재구성 10명·시간 8명·선수개념)와 구조가 1:1인데, 지금 든 텍스트는
   zoviz가 지어낸 것이다. **시연 실측과 교사 실답변으로 교체**하는 것이
   결합의 절반이다.
2. **zoviz 부품이 피드백 해결 장치로 재사용된다.** 배지(11px 대문자 틴트 알약)
   → 용어 칩, 아이콘 타일+항목 제목 → "이 단계에서 할 일" 블록, 카드 규칙
   → 그래프 축 설명 캡션. 새 부품을 발명할 필요가 거의 없다.
3. **디자인이 못 푸는 피드백을 섞지 않는다.** 동시접속 성능·교육과정 불일치는
   화면을 바꿔도 안 풀린다 — 문서와 운영으로 분리한다(§4).

## 6. 논문이 이미 그어놓은 선 — 스캐폴딩의 한계 (§2.3)

> 2026-08-09 추가. 논문 §2.3 을 읽고 §1 의 F3·F4 를 수정했다.
> **초안의 "차이 원인 후보 체크리스트"는 논문의 자기 설계 원리를 위반했다.**

논문 §2.3 은 자동화를 세 열로 나누고, 결론 §6.1 둘째가 이를 다섯 설계 원리
중 하나("결과 해석의 학습자 수행")로 못박는다.

| 플랫폼이 **자동화** | 플랫폼이 **가시화**(학습자가 확인) | **학습자가 직접 수행** |
|---|---|---|
| Python 설치, API 호출, 파일 처리, 서버 계산, 자료 다운로드, 반복 계산 | 데이터 출처, 시간축·밝기값의 의미, 전처리 과정, 분석 조건, 모델 가정 | 그래프 패턴 해석, **기준값과의 차이 설명**, 산출값 의미 해석, 과학적 정당화 |

「기준값과의 차이 설명」이 셋째 열에 있다. 원인 4종을 선택지로 미리 주면
플랫폼이 셋째 열의 일을 대신하는 것이고, 논문이 경고한 실패 모드
("최종 산출값만 제시 → 학습자가 근거를 이해하지 못한 채 결과 수용")를
선택지 형태로 재현하게 된다. 교사 서술 9번의 "버튼만 누르는 주입식" 우려와
같은 지점이다.

**따라서 보완 요구(도움말 7명·기록 강화 7명)는 둘째 열을 두껍게 해서 받는다.**
무엇을 해석해야 할지 막막하다는 Q15 저점은, 답을 주는 것이 아니라 *판단에
필요한 수치를 눈앞에 놓는 것*으로 푼다.

### 단서를 줄여가는 설계(fading)

논문 §2.3 은 이미 이름을 갖고 있다 — "학습자의 숙련에 따라 단서를 점진적으로
줄이는 단계적 스캐폴딩 소거(fading)". 안내를 늘릴지 줄일지의 문제가 아니라,
**언제 거두는지**를 설계하는 문제다. 최소 구현: 학습자가 자기 설명을 제출한
뒤에 비교용 예시가 열린다(먼저 열리지 않는다).

### 탐구 수준 좌표 (Banchi & Bell, 2008) — 확인형 부재는 **결함이 아니라 설계**

논문 §2.3 은 EASWA 가 **구조화형→안내형**을 지향한다고 명시하고, 곧바로
이렇게 덧붙인다 — *"자료 출처·분석 조건·기준값 비교를 학습자가 직접 확인하고
차이의 원인을 스스로 설명하도록 한다는 점에서, **단순 확인형 활동을 넘어**
안내형 탐구의 요소를 포함한다."*

즉 확인형(결과를 이미 아는 상태에서 확인만 하는 수준)을 **의도적으로 범위에서
뺀 것**이고, 논문은 그것을 성취로 서술한다. 설계 원리 5개 중 "수업 적용 가능성
지원"의 근거도 「구조화형→안내형 흐름 + 교사 지원 자료」이지 확인형이 아니다
(§2.4 표). 나아가 "탐구 주제 중심 접근" 원리는 Chinn & Malhotra(2002) 의
**인식론적으로 진정한 탐구(epistemologically authentic inquiry)** 에 근거하는데,
확인형은 그 논문이 비판 대상으로 삼는 쪽이다. **확인형을 앱에 넣으면 논문의
진정성 주장과 충돌한다.**

> **초안의 오류(2026-08-09 정정).** 이 문서 초판은 교사 서술 8번을 "확인형
> 요청"으로 옮겼으나 과잉 해석이었다. 원문은 *"난이도가 조금 더 쉬운 자료
> 해석부터 순차적으로 난이도를 높여가면 좋을 것 같다"* 이고, 앞뒤 문맥이
> 교육과정 적용·심화 선택자 감소이므로 **자료 자체의 난이도 계단**을 말한 것이다
> (쉬운 광도곡선 → 어려운 광도곡선). 이는 구조화형 **안에서** 해결되는 문제이며
> 탐구 수준을 내리는 것과 무관하다.

**따라서 대응은 "쉬운 예제 대상 추가"이지 "확인형 단계 신설"이 아니다.** 예:
식(食)이 뚜렷하고 잡음이 적은 대상을 입문용으로 지정해 먼저 풀게 하는 것.
탐구 수준은 그대로 구조화형이고 논문 문구도 손댈 필요가 없다. §6.2 제언
다섯째의 "난이도 조절"에 자리가 있으므로 후속 과제로 두어도 되고, 대상 목록
정렬만으로 일부는 지금도 가능하다.

### 사용 맥락은 하나로 좁히지 않는다

§5.4 는 1차 조사에서 동아리·과제연구가 더 많이 선택된 것을 **실패가 아니라
구분해야 할 사실**로 적었다 — "플랫폼의 교육적 가치에 대한 인정과 정규
교육과정으로의 편입 가능성은 구분하여 볼 필요가 있으며". §6.2 제언 다섯째도
지구과학 수업·탐구활동·동아리·예비교사 교육·교사연수를 나란히 둔다.
따라서 최종개선은 **정규수업용/동아리용 중 하나를 고르지 않는다.** 현재의
깊이를 유지하되, 정규 차시 편입을 화면으로 주장하지 않고 교사용 자료(§3)와
논문 논의가 받는다.

## 7. 원고 반영 완료 (2026-08-09)

§6 의 분석을 원고(`EASWA_논문_전체수정본_v11.md`)에 적용했다. 백업:
`..._백업_탐구수준정정전_20260809_0206.md`.

**주장 정정 3곳** — EASWA 는 **구조화형**이고 안내형(학습자가 탐구 방법 자체를
설계하는 수준)에는 이르지 않는다고 명시. 학습자 결정권은 «분석 대상과 측광
구경·비교성·분석 구간» 조건 선택으로 한정. 안내형·개방형 확장은 후속 과제로 이동.

- §2.3 본문 / §2.4 설계 원리 표 근거 / 공용 워크플로 표 라벨

**용어 충돌 해소 4곳** — Banchi & Bell 분류어가 아니라 일상어("단계별 안내가
있는")로 쓰이던 '안내형'을 «단계별 안내»·«가이드 투어»로 교체(§3.5, §4.1 표,
§4.1 본문, §4.2 표). 이제 '안내형'은 분류어 용법 2곳(§2.3, §2.4)에만 남는다.

**무변경 확인**: 국문초록, Abstract, 연구문제 4개, 결론 §6.1·§6.2 — 애초에 탐구
수준을 주장하지 않아 파급이 없었다. 서론 §1.4 는 이미 "대상과 분석 조건의 선택
폭을 넓혀 가는 방식"으로 정확히 쓰여 있어 수정 후 §2.3 과 정합된다.

> **웹 설계에 미치는 함의.** 「안내(guided)」는 *교사가 질문을 준다*는 뜻이지
> 소프트웨어가 단계를 짚어준다는 뜻이 아니다. **절차 안내를 늘릴수록 탐구
> 수준은 내려간다.** 따라서 F3~F6 의 안내 강화는 «둘째 열(가시화)»로만 하고,
> 탐구 수준을 올리려면 안내가 아니라 **결정권 이양**(대상·조건 선택 폭)이
> 필요하다. 이는 §6 의 fading 방침과 같은 축이다.

## 8. F3 진단 정정 — 실제 구현을 읽고 나서 (2026-08-09)

**§1 의 F3 는 구현을 확인하지 않고 쓴 것이었다.** 목업을 만들며 실제 코드를 읽으니
Step 5 는 진단보다 훨씬 완성도가 높다.

`ComparisonPanel.tsx`(57줄)는 설정 기반 **정보 패널**일 뿐이고, 실제 비교의 본체는
`TransitComparison.tsx`(348줄)다. 거기에는 이미 다음이 들어 있다.

- **차이의 절대·상대 동시 표기** — 코드 주석이 이유까지 적어 두었다: *"절대차만 주면
  큰 건지 작은 건지 판단할 수 없고, 상대차만 주면 기준값이 작을 때 과장된다.
  둘 다 보여주고 판단은 학습자가 한다."* `%p` 단위 구분까지 처리한다.
- **한 줄 = 항목 · 내 측정 · 문헌값 · 차이** 의 비교표
- **위상 접기 자료 + 내 적합 모델 vs 기대 모델 겹침 그림 + 잔차 서브패널**
- **공전 주기를 비교에서 뺀 이유의 명시** — *"계산해서 정답을 맞힌 것처럼 읽혀
  거짓이 된다"* 는 주석과 함께 «아카이브에서 가져온 입력값»으로 따로 표시
- **χ²_red 를 «단독 판정값이 아니라 해석 근거»로 명시**
- **기준값의 성격 설명** — √(식 깊이) 되짚기라 논문의 Rp/R\* 와 원래 다르다는 것까지
- **원인 후보 안내** — 비교성 선택·블렌딩·구경·ROI

즉 §1 F3 가 «제안»한 것의 상당 부분이 이미 구현되어 있다.

### 그래서 남는 진짜 과제 — 재설계가 아니라 덧붙임 3 + 정리 1

1. **차이의 크기를 재는 기준(σ).** 현재는 «−11.9%»까지만 준다. 그것이 큰지 작은지
   판단할 잣대가 없다. 적합 불확도로 나눈 값을 함께 주면 학습자가 «우연인가»를
   스스로 가를 수 있다. §4.7.1 이 ±0.002 와 해석적 예측치 ±0.0019 의 자기일관성을
   이미 확인해 두어 근거가 있다.
2. **원인 후보를 «문장»에서 «내 설정값»으로.** 안내문이 «비교성·블렌딩·구경·ROI»를
   이름으로만 부르므로, 학습자는 그 값을 보려고 앞 단계로 되돌아가야 한다. 값을 이
   화면에 모으는 것은 §6 의 «가시화» 열에 해당한다 — 답을 주는 것이 아니다.
3. **원인 안내를 «쓴 뒤»로.** 지금은 원인 후보가 학습자가 무엇이든 쓰기 전에 먼저
   보인다. §6 의 fading 을 최소 형태로 적용한다.
4. **(정리) 정보 패널의 «비교값» 칸.** `configs.ts` 의 값이 숫자가 아니라
   «카탈로그 depth와 측정 depth 비교» 같은 **지시문**이라, 바로 아래 실제 비교표와
   같은 말을 두 번 한다. Q12(화면이 복잡하다, 3.50)와 관련될 수 있어 합치거나 걷어내는 안.

# 한국어 문구 규칙 — 번역투를 걸러내는 검사표

> 작성 2026-08-09. 계기: Step 5 목업 문구가 «클로드 특유 영어 직역체»라는 지적.
> 소유자 판단: **UI 형태보다 문구가 더 큰 문제다.**
> 교사 시연에서도 같은 지적이 있었다 — 서술 9번 *"단어, 표현 방법이 AI를 사용한 듯한
> 문맥, 문장, 표현이 있어 자연스럽게 읽히지 않는 설명들이 있었습니다."*

## 0. 먼저 — 앱의 한국어는 대체로 깨끗하다

`frontend/src` 의 한국어 문구 **579개**를 훑은 결과(`ko:` 리터럴 + `lang === 'ko' ?` 삼항):

| 신호 | 건수 |
|---|---|
| **영문 용어 그대로 노출** (aperture · ROI · sector · cutout · blending · contamination · CMD …) | **154** |
| ~할 수 있다 | 9 |
| ~것이다 / ~하는 것 | 3 |
| 관계절 명사구 · 무생물 주어 · ~에 대한 | 각 1 |

긴 문장도 자연스럽다. 예: *"두 별이 공통으로 겪은 변화는 나눗셈에서 상쇄되고, 목표별에만
있는 변화(식 신호)는 남습니다. 그래서 식이 드러납니다."*

**따라서 앱 쪽 과제는 번역투가 아니라 영문 용어 154건이다** — 교사 장벽 2위(9명)로 지적된
`FEEDBACK_ZOVIZ_MAP.md` F2 와 같은 항목이다. 번역투는 **최종개선 때 새로 쓰는 문구**에서
생긴다. 아래 규칙은 그 새 문구를 위한 것이다.

> 표본의 한계: 문자열 리터럴만 셌다. JSX 안에 직접 쓴 한국어와 버튼·라벨 일부는
> 빠져 있으므로, 교사 9번이 본 «AI 같은 표현»이 이 표본 밖에 있을 수 있다.

## 1. 열한 가지 패턴 — 전부 이번 목업에서 실제로 나온 것

### ① 영어 의문문을 그대로 옮긴 제목
- ✗ `이 차이는 큰가` ← *Is this difference large?*
- ✓ `오차와 견주어 보기`

제목은 의문문을 직역하지 말고 **동작을 담은 명사구**로. 굳이 물음표를 쓸 때는
한국어 입말로 — `차이가 왜 생겼을까`.

### ② 관계절을 그대로 옮긴 긴 명사구
- ✗ `차이에 영향을 줄 수 있는 내 설정` ← *my settings that could affect the difference*
- ✓ `분석에 쓴 조건`

영어 `that/which` 절을 «~할 수 있는 N»으로 옮기면 길고 딱딱해진다. **핵심 명사만 남긴다.**

### ③ 영어 은유를 단어 대 단어로 치환
- ✗ `자료가 흔들려 생긴 우연` ← *a coincidence arising from data scatter*
- ✓ `오차 때문에 우연히 이만큼 벌어지기는 어렵습니다`

`scatter`·`jitter`·`noise` 를 «흔들림»으로 1:1 치환하지 말고, **그 상황을 한국어 문장으로
다시 쓴다.**

### ④ 앱의 말투와 어긋나는 종결
- ✗ `…나눠 본다. …보기는 어렵다.` (한다체)
- ✓ `…견주어 봅니다. …어렵습니다.` (합니다체)

앱 기존 문구는 **합니다체**다. 새 문구도 맞춘다. 문서는 한다체여도 되지만 **제품 화면은
합니다체**.

### ⑤ 대시로 이어 붙이기
- ✗ `측광 구경 — 내가 설정`
- ✓ `측광 구경 · 내가 정함`

영어 em dash 습관. 한국어 UI 라벨은 **가운뎃점이나 괄호**를 쓴다.

### ⑥ 시안 주석을 제품 문구에 섞기
- ✗ `이 차이는 큰가덧붙임 ①` — 제목과 리뷰용 표시가 한 덩어리로 읽힘
- ✓ 제목은 그대로 두고, 표시는 **오른쪽 끝에 따로**

`덧붙임 ①` 같은 검토용 표기는 실제 화면에 없는 말이다. 목업에서도 **제품 문구 바깥**에 둔다.

### ⑦ 지시문은 권유형으로
- ✗ `내 측정 오차와 견주어 봅니다.` `…따져 봅니다.`
- ✓ `내 측정 오차와 견주어 봅시다.` `…설명해봅시다.`

서술형(`~합니다`)으로 쓰면 **학습자에게 말하는 게 아니라 앱을 설명하는 글**이 된다.
사실 진술은 `~입니다`, **학습자가 할 일은 `~해봅시다`**.

### ⑧ 안내문에 방법론 세부를 넣지 않는다
- ✗ `여기 문헌값은 아카이브에 실린 식 깊이에 √를 씌워 거꾸로 구했습니다. 논문이 직접
  발표한 반지름비와는 원래 조금 차이가 납니다.`
- ✓ `여기 문헌값은 NASA 아카이브에서 가져온 값입니다. 내가 측정한 값과 얼마나
  차이나는지 비교해보고, 그 원인을 설명해봅시다.`

안내문은 **«이게 뭔지 + 무엇을 할지»** 두 조각이다. 계산 방법·단서 같은 세부는
버리지 말고 **표 아래 작은 글씨**로 내린다.

### ⑨ 학습자가 모르는 용어를 라벨에 그대로 두지 않는다
- ✗ `주연감광 계수 · 모델이 정해 둠`
- ✓ `주연감광 계수 · 별 가장자리가 어두워 보이는 정도`
- ✗ 값이 `시그마 클리핑` → ✓ 라벨에 `크게 튀는 점 자동 제외`, 값은 `기본값 사용`

소유자 지적 — *"학습자가 주연감광 계수라는 내용을 알겠냐고"*. 논문 §2.3 이 모델 가정을
**가시화** 대상으로 규정하므로 감출 수는 없다. 대신 **뜻을 옆에 붙인다**(F2 용어 칩).

### ⑩ 모호한 방향어 대신 구체적으로
- ✗ `무엇이 어느 쪽으로 영향을 줬을지`
- ✓ `결과에 구체적으로 어떻게 영향을 줬을지`

`어느 쪽` 은 영어 *which way / in which direction* 의 흔적이다.

### ⑪ 기능을 말로 알리지 않는다
- ✗ `먼저 쓰고 나면 열립니다 — 같은 자료를 다른 사람들이 어떻게 설명했는지 볼 수 있습니다.`
- ✓ (지운다. 동작으로 보여주고 설명하지 않는다)

소유자 지적 — *"이건 없애. 뭐야 AI 티나게"*. **스캐폴딩 소거(fading)는 그대로 두되
화면에서 announce 하지 않는다** — 쓰고 나면 그냥 열리면 된다.

## 2. 쓰기 전 자가 점검 (5초)

1. 이 문장을 영어로 되돌리면 원문이 그대로 보이는가 → 그러면 직역이다.
2. 제목에 «~할 수 있는», «~에 대한», «~는 것» 이 있는가 → 잘라낸다.
3. 종결이 합니다체인가.
4. 대시(—)를 한국어 문장 안에서 쓰고 있는가.
5. 검토용 표기가 제품 문구에 섞였는가.
6. 학습자가 할 일인데 `~합니다` 로 끝나는가 → `~해봅시다`.
7. 라벨에 학습자가 모를 용어가 그대로 있는가.
8. 기능이 어떻게 동작하는지 말로 알리고 있는가 → 지운다.

## 3. 기계로 셀 수 있는 부분

```bash
python -X utf8 scripts/check_ko_copy.py          # 요약
python -X utf8 scripts/check_ko_copy.py --list   # 해당 문구 전부
```

**기준선 (2026-08-09, 문구 850개):** 영문 노출 **82건** · 번역투 신호 **18건**.
최종개선에서 문구를 새로 쓴 뒤 다시 돌려 **늘지 않았는지** 본다.
`--base 82` 를 주면 늘어난 경우 종료코드 1 로 실패한다.

**판정이 아니라 표본 수집이다** — 자연스러움은 사람이 읽어야 알고, 원어가 맞는
자리(코드 식별자 인용·파일명·논문 제목)도 있다. 용어 결정표는 `docs/TERMS_KO.md`.

# 한국어 문구 규칙 — 번역투를 걸러내는 검사표

> 작성 2026-08-09. 계기: Step 5 목업 문구가 «클로드 특유 영어 직역체»라는 지적.
> 소유자 판단: **UI 형태보다 문구가 더 큰 문제다.**
> 교사 시연에서도 같은 지적이 있었다 — 서술 9번 *"단어, 표현 방법이 AI를 사용한 듯한
> 문맥, 문장, 표현이 있어 자연스럽게 읽히지 않는 설명들이 있었습니다."*

## 0. 먼저 — 앱의 한국어는 대체로 깨끗하다

`frontend/src` 의 한국어 문구 **579개**를 훑은 결과(`ko:` 리터럴 + `lang === 'ko' ?` 삼항):

| 신호 | 건수 |
|---|---|
| **영문 용어 그대로 노출** (aperture · ROI · sector · cutout · blending · contamination · CMD …) | **154** |
| ~할 수 있다 | 9 |
| ~것이다 / ~하는 것 | 3 |
| 관계절 명사구 · 무생물 주어 · ~에 대한 | 각 1 |

긴 문장도 자연스럽다. 예: *"두 별이 공통으로 겪은 변화는 나눗셈에서 상쇄되고, 목표별에만
있는 변화(식 신호)는 남습니다. 그래서 식이 드러납니다."*

**따라서 앱 쪽 과제는 번역투가 아니라 영문 용어 154건이다** — 교사 장벽 2위(9명)로 지적된
`FEEDBACK_ZOVIZ_MAP.md` F2 와 같은 항목이다. 번역투는 **최종개선 때 새로 쓰는 문구**에서
생긴다. 아래 규칙은 그 새 문구를 위한 것이다.

> 표본의 한계: 문자열 리터럴만 셌다. JSX 안에 직접 쓴 한국어와 버튼·라벨 일부는
> 빠져 있으므로, 교사 9번이 본 «AI 같은 표현»이 이 표본 밖에 있을 수 있다.

## 1. 열세 가지 패턴 — 전부 이번 목업에서 실제로 나온 것

### ① 영어 의문문을 그대로 옮긴 제목
- ✗ `이 차이는 큰가` ← *Is this difference large?*
- ✓ `오차와 견주어 보기`

제목은 의문문을 직역하지 말고 **동작을 담은 명사구**로. 굳이 물음표를 쓸 때는
한국어 입말로 — `차이가 왜 생겼을까`.

### ② 관계절을 그대로 옮긴 긴 명사구
- ✗ `차이에 영향을 줄 수 있는 내 설정` ← *my settings that could affect the difference*
- ✓ `분석에 쓴 조건`

영어 `that/which` 절을 «~할 수 있는 N»으로 옮기면 길고 딱딱해진다. **핵심 명사만 남긴다.**

### ③ 영어 은유를 단어 대 단어로 치환
- ✗ `자료가 흔들려 생긴 우연` ← *a coincidence arising from data scatter*
- ✓ `오차 때문에 우연히 이만큼 벌어지기는 어렵습니다`

`scatter`·`jitter`·`noise` 를 «흔들림»으로 1:1 치환하지 말고, **그 상황을 한국어 문장으로
다시 쓴다.**

### ④ 앱의 말투와 어긋나는 종결
- ✗ `…나눠 본다. …보기는 어렵다.` (한다체)
- ✓ `…견주어 봅니다. …어렵습니다.` (합니다체)

앱 기존 문구는 **합니다체**다. 새 문구도 맞춘다. 문서는 한다체여도 되지만 **제품 화면은
합니다체**.

### ⑤ 대시로 이어 붙이기
- ✗ `측광 구경 — 내가 설정`
- ✓ `측광 구경 · 내가 정함`

영어 em dash 습관. 한국어 UI 라벨은 **가운뎃점이나 괄호**를 쓴다.

### ⑥ 시안 주석을 제품 문구에 섞기
- ✗ `이 차이는 큰가덧붙임 ①` — 제목과 리뷰용 표시가 한 덩어리로 읽힘
- ✓ 제목은 그대로 두고, 표시는 **오른쪽 끝에 따로**

`덧붙임 ①` 같은 검토용 표기는 실제 화면에 없는 말이다. 목업에서도 **제품 문구 바깥**에 둔다.

### ⑦ 지시문은 권유형으로
- ✗ `내 측정 오차와 견주어 봅니다.` `…따져 봅니다.`
- ✓ `내 측정 오차와 견주어 봅시다.` `…설명해봅시다.`

서술형(`~합니다`)으로 쓰면 **학습자에게 말하는 게 아니라 앱을 설명하는 글**이 된다.
사실 진술은 `~입니다`, **학습자가 할 일은 `~해봅시다`**.

### ⑧ 안내문에 방법론 세부를 넣지 않는다
- ✗ `여기 문헌값은 아카이브에 실린 식 깊이에 √를 씌워 거꾸로 구했습니다. 논문이 직접
  발표한 반지름비와는 원래 조금 차이가 납니다.`
- ✓ `여기 문헌값은 NASA 아카이브에서 가져온 값입니다. 내가 측정한 값과 얼마나
  차이나는지 비교해보고, 그 원인을 설명해봅시다.`

안내문은 **«이게 뭔지 + 무엇을 할지»** 두 조각이다. 계산 방법·단서 같은 세부는
버리지 말고 **표 아래 작은 글씨**로 내린다.

### ⑨ 학습자가 모르는 용어를 라벨에 그대로 두지 않는다
- ✗ `주연감광 계수 · 모델이 정해 둠`
- ✓ `주연감광 계수 · 별 가장자리가 어두워 보이는 정도`
- ✗ 값이 `시그마 클리핑` → ✓ 라벨에 `크게 튀는 점 자동 제외`, 값은 `기본값 사용`

소유자 지적 — *"학습자가 주연감광 계수라는 내용을 알겠냐고"*. 논문 §2.3 이 모델 가정을
**가시화** 대상으로 규정하므로 감출 수는 없다. 대신 **뜻을 옆에 붙인다**(F2 용어 칩).

### ⑩ 모호한 방향어 대신 구체적으로
- ✗ `무엇이 어느 쪽으로 영향을 줬을지`
- ✓ `결과에 구체적으로 어떻게 영향을 줬을지`

`어느 쪽` 은 영어 *which way / in which direction* 의 흔적이다.

### ⑪ 기능을 말로 알리지 않는다
- ✗ `먼저 쓰고 나면 열립니다 — 같은 자료를 다른 사람들이 어떻게 설명했는지 볼 수 있습니다.`
- ✓ (지운다. 동작으로 보여주고 설명하지 않는다)

소유자 지적 — *"이건 없애. 뭐야 AI 티나게"*. **스캐폴딩 소거(fading)는 그대로 두되
화면에서 announce 하지 않는다** — 쓰고 나면 그냥 열리면 된다.

### ⑫ 앱이 말하는 자리에 «내/내가» 를 쓰지 않는다
- ✗ `내가 측정한 값과 얼마나 차이나는지` · `내 오차 ±0.002` · `구경 · 내가 정함`
- ✓ `측정한 값과 얼마나 차이나는지` · `측정 오차 ±0.002` · `구경 · 직접 설정`

소유자 지적 — *"내가 측정한 값? 말이 이상하게 들리잖아. 내가 누구야 여기서."*
화면은 학습자에게 말하는 자리다. 1인칭을 쓰면 **말하는 사람이 앱인지 학습자인지**
흐려진다. 앱의 `TransitComparison.tsx` 도 `내 측정` 을 쓰고 있어 같은 손질 대상이다.

### ⑬ 용어 풀이는 라벨이 아니라 툴팁으로
- ✗ `주연감광 계수 · 별 가장자리가 어두워 보이는 정도`
- ✓ `주연감광 계수 ⓘ` + 짚으면 뜨는 한 줄 설명

⑨ 를 고치다 라벨이 길어졌다. 소유자 결정 — *"느낌표나 툴팁 넣어서 부가설명 넣는
방식으로."* 용어 목록과 적용 규칙은 `docs/TERMS_KO.md` §1-0.

## 2. 쓰기 전 자가 점검 (5초)

1. 이 문장을 영어로 되돌리면 원문이 그대로 보이는가 → 그러면 직역이다.
2. 제목에 «~할 수 있는», «~에 대한», «~는 것» 이 있는가 → 잘라낸다.
3. 종결이 합니다체인가.
4. 대시(—)를 한국어 문장 안에서 쓰고 있는가.
5. 검토용 표기가 제품 문구에 섞였는가.
6. 학습자가 할 일인데 `~합니다` 로 끝나는가 → `~해봅시다`.
7. 라벨에 학습자가 모를 용어가 그대로 있는가.
8. 기능이 어떻게 동작하는지 말로 알리고 있는가 → 지운다.
9. «내/내가» 가 들어갔는가 → 뺀다.
10. 용어 풀이를 라벨 안에 욱여넣었는가 → 툴팁으로.

## 3. 기계로 셀 수 있는 부분

```bash
python -X utf8 scripts/check_ko_copy.py          # 요약
python -X utf8 scripts/check_ko_copy.py --list   # 해당 문구 전부
```

**«기계가 못 잡는 것»은 없다 — 잡는 층이 다를 뿐이다** (소유자 2026-08-09:
*"못 잡는 게 어디 있어"*). 층은 셋이다:

1. **정규식** — 이 스크립트. ①⑤⑦⑪⑫ 를 포함해 첨삭 패턴 대부분이 여기서 잡힌다.
2. **일괄 리뷰** — 배열 어색함(`자료가 흔들려 생긴 우연` 류)은 패턴이 아니라
   문장 감각의 문제다. 에이전트가 850개를 §1 규칙표에 대고 읽어 **플래그 목록**을
   만든다. 고치지는 않는다 — F-037 이 재작성 실패를 기록했다.
3. **소유자 판정** — 플래그가 결함인지 관례인지는 사람이 정한다. 실제로 이번
   검출에서도 갈렸다: `내 분석 기록` 은 한국 앱의 표준 관례(네이버 «내 정보»)라
   유지 후보이고, 비교표 열 이름 `내 측정` 은 이미 지적받은 그 문제다.

**기준선 (2026-08-09, 문구 850개):** 영문 노출 **82건** · 번역투 신호 **45건**
(패턴 5개 추가 후. 직역 의문형 19 · ~수 있다 9 · 1인칭 8 · 대시 5 · 기타 4).
`--base 82` 를 주면 영문 노출이 늘어난 경우 종료코드 1 로 실패한다.
`--landing` 은 랜딩 한국어 사전을 같은 기준으로 검사한다.

**직역 의문형 19건에 대한 메모** — 대부분 STEP별 질문·생각해보기 문항이다
(`이 탐구에서 관측 자료로 설명하려는 현상은 무엇인가?`). 논문의 설계 요소이고
교사 평가도 좋았다(Q13 평균 4.0). 앱이 합니다체인데 문항만 `-는가?` 문어체라
말투가 갈라진다는 것이 신호의 실체다 — `~일까요?` 로 바꿀지는 소유자 결정 사안.

용어 결정표는 `docs/TERMS_KO.md`.

## 4. 외부 문체 스킬 — 다시 받지 말 것 (F-037)

`im-not-ai` 도입은 **2026-07-31 에 이미 시도했고 두 번 거절당했다.**
`Main/FAILURES.md` F-037 「한국어 문체 스킬을 도입하려다 두 번 거절당했다」.

- 1차 규칙 치환 → *"별론데 ㅋㅋ gpt가 더 잘하는 듯 믿을만한거 맞음?"*
- 2차 문장 재작성 → *"다시 쓴것도 별로임 걍 이건 실패로 마무리"*

**근본원인**: `VOICE_REFERENCE`(소유자가 직접 쓴 원문 = 문체의 기준)를 확보하지 않고
에이전트가 제 감으로 톤을 정했다. 문체는 `TASTE.md` 기준 **L3(사람만 판정)** 이다.

**그 항목이 정한 판별법**: 이 주제가 다시 오면 ① 스킬을 또 받지 말고 ② **소유자가 직접
고친 Before/After 샘플을 먼저 받고** ③ 그 톤에 맞춘다. 스킬을 쓸 자리는 윤문이 아니라
**보존 검사**(수치·인용·각주가 망가졌는지) 하나뿐이다.

### 이 문서의 §1 이 바로 그 샘플이다

2026-08-09 에 소유자가 목업 문구를 한 줄씩 고쳐 주었다. F-037 이 «먼저 받으라»고 한
Before/After 가 이제 있다 — 패턴 ①~⑬ 이 그것이다. **외부 스킬 대신 이 표를 기준으로
쓴다.** 새 문구가 늘어날 때마다 소유자 첨삭을 여기에 추가한다.

### 덤으로 얻은 실측 (F-037, 같은 조사 재실행 금지)

APEX 논문 국문본 33,275자 522문장 측정에서 **전통 번역투는 이미 0건**이었다
(`~를 통해` 0 · `가지다` 직역 0 · 이중피동 0 · `~에 있어서` 0). 실제로 높았던 것은
**긴 대시 33 · 관계절 중첩 40 · 대구 21 · 이중조사 9 · 종결어미 다양도 0.195 · `~다` 연속 30**.

→ `scripts/check_ko_copy.py` 가 세는 `~를 통해` 류는 **이 프로젝트에서 0 으로 나올 가능성이
높다.** 실제로 잡히는 신호는 **긴 대시**이고, 이번 EASWA 스캔에서도 5건이 나왔다.
남은 신호(관계절 중첩·종결어미 다양도)는 아직 스크립트에 없다 — 필요해지면 추가한다.

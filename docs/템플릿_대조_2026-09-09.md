# 학회 논문템플릿 대조 (2026-09-09)

`논문템플릿.hwp` 본문을 추출해 규칙을 뽑고 원고와 대조했다.

## 템플릿이 정한 원고 순서

```
한글제목 → 저자·소속(국문) → 영문제목 → 저자·소속(영문) → 요 약 → 주제어
서론 / 연구 방법 / 연구 결과 / 결론 및 제언
사사
ABSTRACT + Key words
참고문헌
```

**부록 항목이 없다.** 김미림·손정주(2022) 게재본도 참고문헌으로 끝난다.
다만 투고규정 제9조가 따로 허용한다 — 「컴퓨터 프로그램, 참고자료 등은 부록으로 붙일 수 있다.
부록으로 싣기에 너무 큰 자료는 온라인으로 제공할 수 있다.」

## 맞춘 것

| 규칙 | 상태 |
|---|---|
| 국문초록 100–200 단어 | 328 → **200어절** |
| 주제어 2개 이상 5개 이하 | 5개 |
| 표·그림 **아라비아 연번** (예시: 표 1, 그림 1) | 표 3-1·4-1~4-10 → **표 1~11** · 그림 4-1~4-3 → **그림 1~3** |
| 영문초록 위치 (사사와 참고문헌 사이) | 국문초록 뒤 → **참고문헌 앞** |
| 표 제목 뒤 마침표 생략 | 11개 모두 준수 |
| 그림명 뒤 마침표 필수 | 3개 모두 준수 |
| 영문 저자명 (구두점·쉼표 없이 이니셜) | 49건 모두 준수 |
| SI 단위 (숫자와 단위 한 칸) | 해당 표기 없음 |

## 아직 안 맞는 것

### 1. 참고문헌 권(호)

템플릿이 두 형식을 함께 쓴다.

- **제7조 예시**: `새물리 23: 157-159` — 권만
- **템플릿 「참고문헌 예시」**: `초등과학교육 35(3): 277-287`, `현장과학교육 12(3): 297-308` — 권(호)

지금 원고는 권만 쓴다(33건). 게재본이 권(호)를 쓰므로 그쪽으로 통일하는 편이 안전해 보이나,
**호수를 채우려면 33건의 원문이나 서지 정보를 다시 확인해야 한다.**

### 2. 저자 정보

| 항목 | 템플릿 | 원고 |
|---|---|---|
| 교신저자 표시 | 이름 뒤 `*` 윗첨자 | 없음 |
| 소속 | `한국교원대학교 지구과학교육과, 청주시 28173` | 시·우편번호 없음 |
| 교신저자 이메일 | 각주로 | 없음 |
| 접수/수정/통과 | 「학회에서 심사 완료 후 표기」 | 해당 없음 |

### 3. 사사 절이 없다

템플릿에 자리가 있다. ERP 지원을 밝힐지가 게재료와 얽힌다(제12조 2항: 사사를 밝히면 기본
게재료 10만원 → 30만원).

### 4. 부록 둘

- **부록 1. 서술형 응답 범주의 정의와 포함 기준** (28행) — 조판 25~26쪽
- **부록 2. 용어 풀이** (40항목) — 조판 27~28쪽

둘이 조판 4쪽을 차지한다. 빼면 28 → 24쪽.

**판단 근거**

- 부록 1은 **부호화 신뢰성의 유일한 근거**다. 3.6이 「각 범주의 정의와 포함 기준을 부록 1에
  제시하였다」로 가리키고, 부호화자가 한 명이고 일치도 계수가 없는 상태에서 이것을 빼면
  방어가 무너진다. 반대 심문 심사가 이미 그 지점을 공격했다.
- 부록 2는 사정이 다르다. 40항목이 두 쪽을 먹고, 게재본 관행에 없으며, 본문이 용어를 처음
  쓸 때 한 구절로 풀면 대신할 수 있다. v16 검토에서도 「과하다」는 지적이 있었다.

**제안**: 부록 2를 빼고 부록 1만 남긴다. 지면이 더 필요하면 부록 1을 제9조에 따라 온라인
제공으로 돌리고 본문에 그 주소를 적는다.

## 한글이 HTML 을 가져올 때 듣지 않는 것 (실험으로 확인)

`docs/typeset_hwp.py` 가 이 제약 위에 서 있다. 고치기 전에 읽을 것.

| 넣은 방식 | 결과 |
|---|---|
| `<style>` 블록의 `font-family` | **이름이 망가진다** — `KOPUBWORLD바탕체 LIGHT"` 처럼 대문자로 바뀌고 따옴표까지 이름에 들어간다 |
| 요소의 `style="font-family:…"` | 이름 그대로 저장된다 ✔ |
| `<font face="…">` | 이름 그대로 저장된다 ✔ (표 칸은 이 방법만 듣는다) |
| `<style>` 의 클래스 선택자 `.au{font-size}` | 듣는다 ✔ |
| `<style>` 의 요소·후손 선택자 `body{font-size}` · `.abs p{…}` | 듣지 않는다 |
| `<h1>`~`<h4>` | 한글 내장 개요 문단모양이 크기·정렬을 덮어쓴다 — 쓰지 말 것 |
| `<figure>` · `<figcaption>` · `<section>` | 블록으로 보지 않아 그림이 문단 한가운데 인라인으로 박힌다 |
| CSS `margin` | 거의 듣지 않는다 — 빈 문단(`GAP`)으로 간격을 만든다 |
| `page-break-inside:avoid` · `page-break-before` | 듣지 않는다 — 쪽 나누기는 변환 뒤 COM 으로 넣는다 |
| 이미지 크기 | CSS 를 무시하고 픽셀÷96dpi 로 환산한다 — `<img width height>` 로 직접 준다 |
| 표 행 | 쪽 경계에서 갈린다 — 여러 장짜리 그림은 한 장으로 합쳐서 넣는다 |

### 2026-09-09 저녁 추가 — 소유자 지적 세 가지

*「큰 절들도 왼쪽 정렬 그리고 절사이에 줄넘김간격, 페이지 넘어가서 절만 남는 일 없게」*

- **장 제목을 왼쪽으로.** 게재본은 2단이라 가운데였지만 1단에서는 왼쪽이 맞다.
- **절 앞 간격.** CSS margin 이 듣지 않으므로 변환 뒤 문단 모양의 「문단 위 간격」으로
  준다 — 장 15pt · 절 9pt · 캡션 4pt. 장 바로 밑의 첫 절에는 주지 않는다.
- **제목만 쪽 끝에 남는 자리.** 두 겹으로 막는다. ① 모든 제목·캡션에 「다음 문단과
  함께」를 켠다. ② 그래도 본문이 한 줄만 따라오는 자리가 남으므로, 조판 결과를 PDF 로
  뽑아 줄 수를 세고 모자란 제목 앞에 쪽 나누기를 넣는다. 장 제목 밑에 절 제목이 오는
  자리에서는 **위의 것부터** 넘긴다 — 아래 것만 넘기면 장 제목이 혼자 남아 끝나지 않는다.

함께 고친 것.

- **그림 해상도.** 한글의 HTML 가져오기는 그림을 무조건 96dpi 로 다시 샘플링한다
  (5770px 원본 → 582px). HTML 에는 `[[FIG n]]` 표시만 넣고 COM 의 `InsertPicture` 로
  원본을 넣은 뒤 개체 속성으로 mm 크기를 준다. 219 / 543 / 952 dpi 로 들어간다.
- **PDF 로 내보낸 문서를 그대로 다시 저장하면 그림이 96dpi 로 줄어든다.** 쪽 나누기를
  검사하는 판과 고치는 판을 따로 연다.
- **표 폭.** `width:100%` 를 무시하고 150mm 로 넣으므로 COM 으로 본문 폭 165.5mm 로.
- **열 너비.** 한글이 열을 균등 분할해 「수행 내용」이 여섯 줄로 접혔다. 칸 글자 수
  (최댓값과 평균을 반씩)로 비율을 정해 `<th width="n%">` 로 준다.

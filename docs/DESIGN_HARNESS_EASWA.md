## 0. 이 하네스가 하는 일과 안 하는 일

**한다** — 화면을 만들기 전에 고정할 것을 못 박고, 만든 뒤 기계와 눈으로 각각 검사한다.

**안 한다** — 점수를 매기지 않는다. 100점 총점도, 항목별 감점 가중치도 쓰지 않는다.
근거로 쓴 커뮤니티 조사는 「어떤 항목이 더 자주 지적되는가」의 순서만 지탱하고,
그 순서를 가중치로 바꾸면 **말로 이름 붙이기 어려운 결함(밀도·위계·정렬)이 0점이 된다.**
이 프로젝트에서 실제로 세 번 지적된 것이 전부 그쪽이다. 그래서 통과·불통과 목록이다.

**가장 중요한 경고.** 2026년 기준 가장 강한 「AI가 만든 티」는 보라색 그라디언트가 아니라
**직전 세대의 안티-AI 조언이 수렴해서 만든 «취향처럼 보이는 기본값»**(크림 배경 + 세리프
제목 + 세이지 그린)이다. 규칙을 더 잘 지킨다고 벗어나지지 않는다.
**벗어나는 방법은 하나뿐이다 — 이미 가진 것에 고정하는 것.** 그게 §1 이다.

## 1. 고정 — 바꾸지 않는다

이 절은 협상 대상이 아니다. 새 화면이 여기서 벗어나면 그 화면이 틀린 것이다.

| 항목 | 값 |
|---|---|
| 바탕 | `#0b0e14` · 두 번째 면 `#12161e` · 카드 `#1a2030` |
| 테두리 | `#252d3a` (밝게 `#2e3848`) |
| 글자 | 제목 `#eceff4` · 본문 `#d4dae5` · 보조 `#9aa3b0` · 흐림 `#98a2b3` |
| 강조 | 주황 — 다크 `#e8722a` · 흰 바탕 `#b95314`. **한 화면에 4점 이하** |
| 로고 | 소유자 제공 «E + 궤도» 마크. **단색**이라 바탕색을 따라간다 — 주황 예산을 쓰지 않는다 |
| 서체 | Pretendard. 숫자는 `tabular-nums` |
| 모서리 | 6 / 8 / 12 px. 알약(999px)은 배지·칩·점에만 |
| 그림자 | 없음. 모달·팝오버만 예외 |
| 글로우 | **없음** |
| 그라디언트 | **없음.** 사진과 과학 색지도는 예외 |

- 다크 기조는 그 자체로 「AI 티」가 아니다. 커뮤니티 조사에서 **다크 모드는 기각 항목**이다.
  문제로 잡히는 것은 이유 없는 글로우뿐이다.
- **다만 «AI 티가 아니다»가 «읽기 좋다»는 뜻은 아니다.** 읽기 성능은 흰 바탕이 유리하고
  글자가 작을수록 격차가 커진다. 그래서 규칙은 이렇다 — **자료를 보는 캔버스(전천·플롯·
  관측 이미지)는 어둡게, 읽고 고르는 화면(홈·목록·표·기록)은 밝게.**
  근거와 계산은 `DESIGN_COLOR_LIGHT_VS_DARK.md`.
- 주황을 어디에 쓸지 매번 센다. 주 행동 버튼 · 현재 위치 표식 · 핵심 값 하나 · 경고 하나.
  넷을 넘으면 하나를 뺀다.
- 선택·활성 상태는 **배경 채움 금지 · 왼쪽 세로 강조선 금지.**
  글자를 희게 + 굵게, 필요하면 앞에 점 하나.

## 2-1. 어디에 적용되는 규칙인가 — 2026-09-05 수정

**§3 과 §4 는 탐구활동 화면 규칙이다. 랜딩(홈)에 그대로 씌우면 화면이 죽는다.**

소유자 지적 — *"왤케 밋밋하지 글만 주루룩 나열된느낌"*, *"하네스.... 이거 참문제네"*.
§3 의 「상자 안의 상자를 만들지 않는다 · 구조는 여백과 얇은 선이 만든다」를 홈에까지
적용해 큰 그림을 작게 줄이고 모든 구역을 같은 흰 바탕에 텍스트 행으로 눌러 놓았다.
그건 계기판 장르의 규칙이지 랜딩 규칙이 아니다.

| | 탐구활동 화면 | 랜딩(홈) |
|---|---|---|
| 상자 | 테두리 상자 한 겹까지 | 구역마다 **바탕색을 바꿔** 리듬을 만든다 |
| 그림 | 플롯이 주인공, 장식 이미지 최소 | **크게 쓴다.** 좌우 교대, 높이 360px 이상 |
| 히어로 | 없음 | **높이는 내용이 정한다.** 예전에 적었던 360~460px 상한은 폐기 |
| 아이콘 | 쓰지 않는다 | 선 아이콘 타일로 그룹 시작을 표시해도 된다 (이모지는 여전히 금지) |
| 문구 | 판단을 돕는 안내 | **짧고 세게.** 구역 제목은 한 줄, 설명은 한 문장 |

§1(고정 팔레트)·§2(기계 검사)·§5(한국어)는 두 장르 모두에 적용된다.

## 3. 눈으로 재는 것 — 기계가 못 잡는 쪽

커뮤니티 조사에서 이 항목들은 언급률이 0.0~0.3% 였다. **드물게 언급된다는 뜻이지
덜 중요하다는 뜻이 아니다.** 사람들은 이름 붙이기 쉬운 색과 프레임워크만 말한다.

1. **밀도.** 한 화면에 큰 덩어리 2~6개. 작은 상자를 격자로 늘어놓지 않는다.
   지표와 조건은 개별 카드가 아니라 **한 덩어리 안의 가는 구분선 행**으로 쌓는다.
2. **상자 안의 상자를 만들지 않는다.** 구조는 여백과 얇은 선이 만든다.
   테두리 상자는 한 겹까지.
3. **위계는 색이 아니라 크기와 굵기로.** 제목과 본문의 층이 얕으면 다시 잡는다.
4. **정렬.** 거의 맞고 완전히는 안 맞는 가장자리를 남기지 않는다.
5. **주인공이 있다.** 탐구 화면은 그래프가 60% 이상. 홈은 실제 자료 이미지가 주인공.
6. **말투.** 신호등 이모지 금지, 지시형 어투에 화살표 붙이기 금지, 한 문장에 조건·예외를
   몰아넣지 않기, 앱이 스스로를 「내가」라고 부르지 않기.

## 3-1. 절제를 어디에 적용하나 — 2026-09-05 추가

**절제는 정보 밀도에 적용하고, 행동 유도에는 적용하지 않는다.**

소유자 지적 — *"탐구블럭들이 경계가 잘 안읽히고 버튼감들도 좀 없고 모듈인가?
그냥 사진과 글인가?"*. §3 의 「상자를 쓰지 않는다」를 모듈 목록에까지 밀어붙인 결과다.

- **누를 수 있는 것은 누를 수 있게 보이게 만든다.** 면을 채우거나, 테두리를 뚜렷하게
  하거나, 최소한 주변과 다른 표면 위에 올린다.
- **외곽선만 있는 버튼을 주 행동에 쓰지 않는다.**
- **목록의 항목이 각각 독립된 대상이면 경계를 그린다.** 여백만으로 나누지 않는다.
- 채워진 면 자체가 행동 유도다. **색으로 유도하지 않는다** — 버튼 면은 먹색으로 하고
  주황은 화면당 하나로 남긴다.

근거는 `DESIGN_EVIDENCE_AFFORDANCE_2026-09-05.md`. 요지만 적으면, 테두리를 지운 화면에서
누를 수 있는 것을 **못 알아본 비율 26.0% → 35.8%**, **잘못 누른 비율 16.6% → 28.0%**
(Burmistrov 외 2015, N=20, 시선추적, 셋 다 p<0.01). 시민과학 기술 설계 지침 62편
종합(Skarlatidou 외 2019)의 권고 중 하나도 「버튼을 더 크게 만들 것」이다.

## 4. 화면 구성

### 홈

- 히어로 높이는 **내용이 정한다.** (2026-09-05: 360~460px 상한 폐기 — 소유자가
  *"메인히어로 페이지맨위에거, 세로 좀더 키워"* 라고 지시했고, 실제로 그쪽이 낫다.)
- 히어로 안에 들어가는 것 — 로고, 짧은 길잡이, 실제로 무슨 일을 하는지 설명하는 제목,
  **주 행동 하나**, 실제 천문 이미지와 출처. 보조 행동은 글자 링크로.
- 「우주를 열어보세요」류 문구 금지. 무엇을 하는지 그대로 쓴다.
- 모듈 목록은 **한 줄에 하나**, 세로로. 3개용 3칸 격자 금지.
- **지금 3개가 아니라 20개를 기준으로 짠다.** 번호를 매기고, 자료원·난이도로 거를 자리를
  만든다. 아직 못 거르면 **숨기지 말고 왜 안 되는지 적는다.**
- 모듈 한 줄에 들어가는 것 — 실제 과학 이미지와 출처, 번호와 자료원, 제목, 대표 탐구 질문,
  자료·분석·비교 기준·수업의 네 줄, 행동 하나.

### 탐구활동 화면

- **구조를 바꾸지 않는다** (2026-08-14 결정). 좌측 흐름 + 중앙 작업 + 우측 결과를 유지하고
  글자 크기·굵기·간격만 손본다. 히어로·큰 제목 같은 랜딩 문법을 들여오지 않는다.
- 중요한 수치는 **측정값 · 불확실도 · 기준값 · 차이 · 단위 · 출처**를 같은 표에 둔다.
  **없는 불확실도는 만들지 않는다.**
- 결과 그림과 표에는 출처를 **빠짐없이** 붙인다.
- 도움말은 지금 하는 일 옆에서 열린다. 다른 화면으로 보내지 않는다.

#### 4-1. 도구 화면에만 적용되는 다섯 (2026-09-05 추가)

근거는 `DESIGN_EVIDENCE_TOOL_SCREENS_2026-09-05.md`.

1. **설명은 그림 옆에 둔다.** 광도곡선과 그 설명·질문을 다른 패널로 떼지 않는다.
   글과 그림을 붙여 두는 것(인접성)이 다중매체 원리 중 효과가 가장 크다 —
   **g = 0.74**, 다음이 그림+글 0.39·신호주기 0.38, 전체 평균 0.37
   (Mayer 연구 메타분석 2025, 92편·181연구·591효과).
2. **밀도는 커뮤니티가 아니라 대상이 정한다.** 실무자 의견은 갈려 있다 —
   「한 화면에 너무 많다」 7.5% 대 「전문가는 밀도를 원한다」 7.2% (HN 1,731건).
   EASWA 대상은 초보이므로 **한 화면에 큰 덩어리 2~6개.** 현재 Step 0 은 12개다.
3. **되돌리기와 이력을 넣는다.** 분석 조건을 바꿔가며 시도하는 화면에는 「방금 설정으로
   되돌리기」가 있어야 한다. Shneiderman(1996) 일곱 과제 중 **History** 가 지금 빠져 있다.
4. **분석 조건을 값으로 꺼낼 수 있게 한다** (Extract). 기록에 결과만이 아니라
   **어떤 조건으로 얻었는지**가 함께 남아야 한다.
5. **동작은 이름 붙은 버튼으로.** 문자 글리프(`❚❚`)와 화살표 접두(`← 이전 단계`)를
   쓰지 않는다. NASA Exoplanet Archive 는 40,144행짜리 표에서도 모든 동작에 이름을 붙이고
   숨긴 메뉴를 두지 않는다.

**단계 잠김은 유지한다.** 순서대로만 진행되는 것은 Quintana 지침 4a·4c(경계 설정,
기능 모드로 활동 공간 제한)에 해당하는 **설계**다.
검토·자동 캡처는 `?target=<id>&blockStep=<단계 id>` 로 가능하다 — 5·6단계만 적합 결과를
요구한다.

## 5. 한국어

`docs/KOREAN_COPY_RULES.md` 의 14가지 패턴과 `docs/TERMS_KO.md` 의 표기 표를 따른다.
새로 만드는 화면에서 특히 이 셋.

1. **영문 대문자 라벨을 쓰지 않는다.** `DATA`·`ANALYSIS`·`COMPARE`·`PROVENANCE` 같은
   표 머리는 한국어로. 학습자가 읽는 자리다.
2. **첫 등장은 「한국어(영문)」, 다음부터 한국어만.** 고유명사와 미션명(TESS·Gaia·KMTNet·
   MAST)은 그대로 둔다.
3. **라벨 안에 뜻풀이를 넣지 않는다.** 작은 `ⓘ` 를 달고 짚으면 한 줄이 뜨게 한다.

근거가 밖에도 있다 — 시민과학 기술 설계 지침 62편 종합(Skarlatidou 외 2019)의 첫 항목이
«익숙한 이름을 쓸 것»이고, 과학탐구 소프트웨어 비계 설계 프레임(Quintana 외 2004)의
지침 1b 가 «학습자의 직관을 딛는 설명»이다.

## 6. 만들 때 순서

1. 이 화면의 과학적 과제를 한 문장으로 쓴다.
2. 주 행동 하나를 정한다.
3. **과학적 대상부터 놓는다** — 그림·표·수치·출처·조작 도구.

6. 빌드하고 5895 에서 실제로 띄워 캡처한다. 개발 서버(5173)는 캡처가 멈춘다.

8. 비포·애프터 캡처 쌍으로 보고한다.

## 7. 왜 이 프레임인가 — 학습 환경 쪽 근거

EASWA 는 연구자용 자료실이 아니라 **학습 환경**이다. 비교 대상도 그쪽이어야 한다.

Quintana 외 (2004) 의 과학탐구 소프트웨어 비계 설계 프레임(7지침·18전략)이 EASWA 의
5개 설계 원리와 거의 일대일로 맞는다.

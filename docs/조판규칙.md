## 2. 한글이 무시하는 것 — 사고의 대부분이 여기서 났다

CSS 로 주면 브라우저에서는 보이는데 한글에서는 사라지는 것들이다. 그래서 아래 것들은
`make_hwp.py` 가 변환 뒤에 한글 명령으로 다시 준다.

| CSS | 한글에서 | 대신 쓰는 것 |
|---|---|---|
| `<style>` 안의 `font-family` | 이름을 대문자로 바꾸고 따옴표까지 글꼴 이름에 넣는다 | 요소마다 `style="font-family:…"`. 표 칸은 `<font face>` |
| `margin` (문단 사이) | 거의 무시 | `문단.json` 의 `prev` + `ParagraphShape` |
| `page-break-after:avoid` | 무시 | `KeepWithNext` + PDF 를 재서 쪽 나누기 삽입 |
| `page-break-before:always` | 무시 | `break_before()` 가 `BreakPage` 를 넣는다 |
| `text-align:center` (그림) | 무시 | `ParagraphShapeAlignCenter` |
| `max-width` / `max-height` (그림) | 무시하고 96dpi 로 환산 | HTML 에는 크기를 안 적고 COM 으로 mm 지정 |
| `@page { margin }` | 무시 | `PageSetup` 의 `PageDef` |
| 표의 `width:100%` | 무시 | 표 컨트롤의 `Width` 를 166.0mm 로 |

**그림에 `<img width height>` 를 적으면 안 된다.** 한글이 그 픽셀 수에 맞춰 원본을 다시
샘플링한다 — 5770px 원본이 582px 로 줄었다. 그래서 HTML 에는 `[[FIGn]]` 표시만 두고
`place_figures()` 가 원본을 넣은 뒤 크기를 준다.

### 머리말 세 종류는 HWPX 로 넣는다

템플릿은 1쪽에 「\| 연구논문\|」과 학회지명을 한 줄에 두고, 2쪽부터 홀수 쪽에 학회지명,
짝수 쪽에 논문 제목을 넣는다. **한글 COM 으로는 이것을 만들 수 없다** —
`HeaderFooter` 액션에 `ApplyClass`·`WhichPage`·`Where` 를 무엇으로 줘도 머리말 컨트롤이
하나만 생기고 마지막 것이 앞의 것을 덮는다(2026-09-10 확인).

HWPX 는 ZIP + XML 이라 머리말이 이렇게 보인다.

```xml
<hp:ctrl><hp:header id="1" applyPageType="ODD"> … </hp:header></hp:ctrl>
```

`applyPageType` 이 BOTH·ODD·EVEN 세 값을 갖고, 같은 구역에 컨트롤을 둘 넣으면 한글이
홀수·짝수를 나눠 찍는다. `docs/hwpx_headers.py` 가 hwp 를 hwpx 로 바꾸고, 머리말
컨트롤을 복제해 값을 바꾼 뒤 다시 hwp 로 되돌린다. 이 구조는 사장님이 알려준
[hwpx-skill](https://github.com/jkf87/hwpx-skill) 의 `fill_hwpx.py` 에서 확인했다.

- **1쪽만 다른 머리말은 구역으로 가른다.** `make_hwp.py` 의 `break_section` 이 서론 앞에서
  구역을 나누므로 section0 이 표제부, section1 이 본문이다. 구역을 나누면 새 구역은
  머리말을 물려받지 않으므로 첫 구역의 컨트롤을 본으로 삼아 넣는다
- **가운데로 보내는 일은 탭이 한다.** 문단 모양을 바꾸면 머리말이 본문 스타일을 물고 와
  크기까지 달라진다. 탭 넷이 x93, 다섯이 x93 — 템플릿의 홀수 쪽 x89.9 와 3mm 차이다
- 텍스트 요소 안에 탭 컨트롤이 섞여 있다(`<hp:t>글자<hp:tab/>글자</hp:t>`). `[^<]*` 로
  잡으면 통째로 빗나간다

1쪽은 표제부와 두 초록, 교신저자 각주까지 담고 본문은 2쪽에서 시작한다.

## 4. 표

### 4.1 열 너비 — 보장하는 것은 「가장 긴 낱말」이다

머리글 전체를 한 줄에 넣으려 들면 안 된다. 머리글이 다 긴 표에서 최소 폭의 합이
100% 를 넘고, 부족분을 넉넉한 열에서 빼는 과정에서 **짧은 머리글 열 하나가 부담을 다
진다.** 표 10 의 「응답」 열이 5%(8.8mm)까지 좁아져 글자가 세로로 한 줄씩 쌓였다.

그래서 `col_floor()` 가 보장하는 것은 그 열에서 **가장 긴 낱말 하나**가 들어갈 폭이다.
낱말은 공백·가운뎃점·슬래시에서 끊는다. 머리글이 두세 줄로 접히는 것은 정상이다.

- 희망 폭 = (가장 긴 칸 + 평균) ÷ 2 를 비율로
- 하한 = 가장 긴 낱말 + 칸 여백 3.2mm + 여유 1mm
- **숫자만 든 열은 13% 를 넘기지 않는다** — 넓혀 봐야 빈칸이고 글이 든 열이 좁아진다

### 4.2 선 — 가로선만, 무리 사이에만

게재본이 그렇다. 세로선은 긋지 않는다.

- 머리행 위 1.14pt, 머리행 아래 0.36pt, 마지막 행 아래 1.14pt
- 본문 행 사이 0.36pt
- **첫 칸이 빈 행은 위 행과 같은 무리로 보고 선을 긋지 않는다.** 20행짜리 표 12 가
  행마다 선이 그어져 읽히지 않았다(2026-09-10 소유자 지적)

### 4.3 캡션

표 위에 두고, 위 간격 9pt 를 준다. 4pt 로 뒀더니 그림 캡션 바로 뒤에 붙어 한 덩어리로
읽혔다. 표 뒤에는 5pt 짜리 빈 문단을 둔다.

### 4.4 쪽에서 갈리는 표

**한글은 갈린 표의 다음 쪽에 머리행을 되풀이해 주지 않는다.** 표 속성의 「나누지 않음」
(`PageBreak=2`)은 저장은 되지만 배치에 듣지 않는다(2026-09-10 확인). CSS 의
`page-break-inside` 도 무시한다. 그래서 **저장한 뒤 PDF 를 재서 갈린 표를 찾아 그
캡션 앞에 쪽 나누기를 넣는다**(`make_hwp.py` 의 `fix_split_tables`).

- 20행이 넘는 표만 갈리도록 둔다. 표 12(20행)는 통째로 넘긴다
- 한 번 민 표가 그래도 갈리면 더 밀지 않는다 — 한 쪽에 안 들어가는 표다(표 6).
  앞 쪽만 비운다

## 7. 왜 이 경로인가 — 다른 길을 다시 재지 않도록

| 경로 | 판정 |
|---|---|
| **HTML → 한글 (지금)** | 표·그림·글꼴이 함께 넘어간다. 한글이 무시하는 것은 COM 으로 보정한다. 검증 끝 |
| DOCX → 한글 | 한글이 DOCX 를 연다. `python-docx` 로 만들면 표 서식을 더 정확히 줄 수 있다. **다만 한글이 무시하는 목록(2절)은 그대로 남는다** — 여백·간격·그림 크기는 어차피 COM 으로 준다. 지금 경로가 도는 한 갈아탈 이유가 없다 |
| PDF → 한글 | 쓰지 않는다. 한글이 PDF 를 열면 글자를 재배치해 표가 깨진다 |
| 브라우저 인쇄로 PDF | 미리보기용으로만. `--preview` 판이 그것이다 |

## 8. 이미 저지른 실수 — 다시 하지 않는다

- 중간 HTML 을 크롬으로 PDF 로 뽑아 완성본이라고 냈다. 그림이 없고 여백이 첫 쪽에만
  있었다 (`Main/FAILURES.md` F-318)
- 여백을 요소 padding 으로 줬다. 둘째 쪽부터 사라졌다
- CSS 를 `@media print` 안에 넣었다. 크롬 화면과 한글에서 둘 다 안 보였다
- 장 제목을 양단으로 걸었다. 앞 쪽이 통째로 비었다
- 표의 숫자 칸을 지우는 정규식을 썼다. 「1 / 0」과 「—」가 사라졌다
- 투고본이 2단인 줄 알았다. 논문템플릿.hwp 는 1단이다
- 표 머리글을 한 줄에 넣으려다 짧은 머리글 열을 8.8mm 로 눌렀다. 글자가 세로로 쌓였다
- 그림을 좁히면 쪽이 덜 빌 줄 알았다. 그림과 캡션이 한 덩어리라 오히려 더 비었다
- 부록을 조건 없이 새 쪽으로 밀었다. 참고문헌 한 줄만 있는 쪽이 생겼다

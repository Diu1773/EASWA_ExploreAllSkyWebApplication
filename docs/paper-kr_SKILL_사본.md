# 한국어 학술 원고 지침

EASWA 논문(현장과학교육 투고)을 2026-09-06 ~ 09-10 에 정리하면서 **실제로 걸린 것**만 담았다.

**순서가 중요하다.** 이 세션에서 사람이 가장 많이 지적한 것은 문체가 아니라
**절이 자기 자리를 벗어나는 것**이었다. 1~5절이 그 규칙이고, 문체는 8절부터다.

**문체를 고친 뒤에는 11-B 로 돌아온다.** 대규모 교정은 뜻을 함께 움직인다. 한 번은
「일반화할 수 없다」가 원고에서 통째로 사라졌고, 같은 날 다른 자리는 「시사한다」가
「해야 한다」로 세졌다. 교정 전 판본과 대조하지 않으면 둘 다 안 보인다.

# Ⅰ. 구조 — 절이 하는 범위

## 1. 논문은 모래시계다

소유자 원문 — *「논문은 모래시계 형태니깐 서론에서 점점 좁아지다가 결과 이후 다시 커지는 거지.」*

```
서론      넓다 → 좁다
이론      각 절이 원리 하나씩
방법      가장 좁다
결과
논의      좁다 → 넓다
결론
```

**절 번호가 순서다.** 2.2 는 두 번째 이론이고 2.3 은 세 번째다. 각 절은 앞 절보다 좁고
뒤 절보다 넓다. 여기서 규칙 하나가 따라 나온다.

> **한 절이 자기 자리보다 넓거나 좁은 것을 말하면 그 절이 틀린 것이다.**
> 서론이 결과를 말하면 너무 좁고, 이론이 구현 세부를 말하면 너무 좁고,
> 결과가 해석을 말하면 너무 넓다.

## 2. 전 장 공통 규칙 여섯

| 규칙 | 뜻 |
|---|---|
| **한 사실은 한 곳에서 처음 말한다** | 다른 장은 절 번호로 가리킨다(「(1.3)」·「(4.5)」). 같은 문장을 두 장에 두지 않는다 |
| **인용은 장마다 역할이 다르다** | 서론 = 「이런 연구·도구가 있다」까지 · 이론 = 그 문헌이 무엇을 밝혔고 우리 설계에 어떻게 닿는가 · 논의 = 우리 결과와의 대조. 같은 문헌을 세 장에서 써도 되지만 **같은 논지로 쓰면 중복**이다 |
| **결과 수치는 결과 장에서 처음 나온다** | 논의·결론의 수치는 결과 장에 있어야 한다. 문헌 수치는 인용과 같은 문장이면 예외 |
| **당위는 서론까지** | 「~해야 한다」·「~할 필요가 있다」는 서론의 설계 방향 절까지. 방법 이후는 무엇을 했고 무엇이 나왔는지만. 제언 절에서 다시 허용 |
| **못 하는 주장은 어느 장에도 안 들어간다** | 3절 참조 |
| **검토 범위를 벗어난 서술을 하지 않는다** | 구현했다고 검토한 것이 아니다 |

## 3. 못 하는 주장 — 자료가 없으면 쓰지 않는다

시작할 때 **「이 자료로 못 하는 말」 목록을 먼저 만든다.** EASWA 의 목록은 여섯이었다.

| 못 쓰는 말 | 왜 |
|---|---|
| 학습 효과·성취 향상 | 학생 대상 조사를 하지 않았다 |
| 보완 전후 개선 효과 | 두 회차는 집단·산출물·문항이 함께 달라졌다 |
| 일반화 | 표본이 작고 자발적 참여이며 진행자가 개발자 본인이다 |
| 도구를 안 썼을 때와의 비교 | 대조군이 없다 |
| 반복·장기 효과 | 1회 수행 자료뿐이다 |
| 「부담이 줄었음을 검증하였다」 | 가진 것은 완주율·소요시간·반응이다 |

**목록을 만들어 두면 나중에 「이거 써도 되나」를 매번 다시 묻지 않는다.**
부정문으로 밝히는 것(「~는 검증하지 않았다」)은 허용된다. 다만 문법은 바꿀 수 있다 —
4절 참조.

## 4. 못 하는 주장을 막는 문장도 꼴은 바꿀 수 있다

**주장을 남기라는 뜻이지 문법까지 남기라는 뜻이 아니다.**

| 지금 | 대신 |
|---|---|
| 모든 서비스를 포괄하는 사용성 비교가 아니다 | 사례분석의 범위는 목적 표집한 네 서비스에 한정되며, 서비스 간 비교는 수행하지 않았다 |
| 개발 방식을 비교해 얻은 결과가 아니라 | 개발 방식 간 비교는 연구 범위에 포함하지 않았다 |
| 우열을 비교하는 값이 아니다 | 각 조건 안에서 적합도를 확인하는 지표이며, 조건 간 비교에는 사용하지 않았다 |

## 5. 순환논리 — 근거가 결론을 미리 담고 있는 자리

소유자 원문 — *「순환논리 쓰던것들 사례분석이랑 설계원리들, 3장에만 있는게 아닐
가능성이 있어 논문전체에 걸쳐서 있을거야」*. 실제로 초록·서론·표·방법·결론 다섯 곳에
남아 있었다. **한 절만 고치고 끝내면 그대로 나간다.**

위험한 자리는 셋이다.

| 자리 | 무엇이 순환인가 | 어떻게 막나 |
|---|---|---|
| **분석 기준 ↔ 설계 원리** | 분석 기준과 설계 원리가 같은 대목을 다루면, 「기준으로 재 보니 원리가 나왔다」는 답을 정해 놓고 잰 것이다 | 원리의 근거는 이론과 교육과정 검토이고, 사례분석은 그 방향이 실제로 요구되는지 **확인하는** 자료라고 밝힌다 |
| **사용자 응답 ↔ 원리의 타당성** | 「반응이 높게 나왔으니 원리가 타당하다」 | 응답은 보완 지점을 찾는 형성적 자료다 |
| **산출값 점검 ↔ 코드 정확도** | 점검 스크립트가 본체와 함수를 공유하면 서로를 검증하지 못한다 | 「독립 검증은 이 점검의 범위에 포함하지 않았다」 |

## 6. 작업 순서 — 뒤에서부터, 기준점을 먼저 잠근다

소유자 원문 — *「지금 원고는 앞에서부터 작업하면 또 순환한다」*.

**앞에서부터 고치면 순환한다.** 서론을 고치면 이론이 어긋나고, 이론을 고치면 결과가
어긋나고, 결과를 고치면 다시 서론이 어긋난다. EASWA 에서 이틀 동안 실제로 그렇게 돌았다.

```
설계 원리(결과 장) → 이론 → 방법 → 결과 → 서론 → 논의 → 결론 → 초록
```

**기준점을 하나 정해 먼저 잠근다.** EASWA 의 기준점은 「다섯 설계 원리」였다.
여기를 확정해야 이론과 방법의 순환이 끊긴다.

곁들여 지킨 규칙 넷.

1. **고정 문서에 없는 것은 고치지 않는다.** 고칠 일이 생기면 고정 문서를 먼저 고치고
   원고를 맞춘다. 목표·연구문제를 문서로 잠그지 않으면 서론이 매번 엎어진다
   (EASWA 는 이틀에 세 번 엎어졌다).
2. **한 절은 한 번만 연다.** 여는 날에 끝낸다.
3. **새 초안이 오면 먼저 고정 문서와 대조한다.** 어긋난 곳을 목록으로 내고 반영은 그다음.
4. **「관행」은 표본을 세고 쓴다.** 표본이 둘 이하이거나 저자·연구실이 겹치면 관행이
   아니라 「이 두 편에서는 이랬다」이다. 규정 문서가 있으면 논문 표본보다 규정을 먼저 읽는다.

# Ⅱ. 목차와 제목

## 7. 소제목은 이름을 붙이고 주장을 하지 않는다

| 고칠 꼴 | 예 | 대신 |
|---|---|---|
| 대시(—) 부제 | 「왜 며칠 앞인가 — 오늘 밤 정보밖에 없다」 | 「다일 예보의 필요」 |
| 단정형 「~다/했다」 | 「아카이브를 직접 지었다」 | 「아카이브 구축」 |
| 부정으로 끝내기 | 「누수가 없다」 | 「시간 블록 교차검증」 |
| 의문형 「왜 ~인가」 | 「왜 v12 전용인가」 | 「v12 로 한정한 이유」 |
| 대구 | 「무엇이 되고 무엇이 안 되나」 | 「결과의 적용 범위」 |
| 결과 수치 | 「6칸 중 2칸만 통과」 | 「주변보정 결과」 |

**결론 문장을 제목 자리에 두지 않는다.** 「2.2 라벨은 전달 영상품질이다 — 대기 시잉이
아니다」는 소제목이 아니라 결론이다. 그 구분은 절 안에서 진술한다.

영문 저널이면 한국어 제목이 번역 발판이다. **발판이 수사적이면 영어도 물려받는다.**

# Ⅲ. 문체 — 실측 기준선으로 잰다

## 8. 에세이 기준을 쓰면 안 된다

`humanize-korean` 스킬의 실측 기준(KatFish 코퍼스)은 **칼럼·에세이·위키**다.
학술 논문에 그대로 대면 정상인 것이 AI 로 잡힌다.

| 지표 | 에세이 기준 | 한국어 학술논문 12편 |
|---|---|---|
| 쉼표를 가진 문장 | 사람 26.3% · AI 61.0% | 중앙값 **59.7%** |
| 연결어미 뒤 쉼표 | 사람 4.1% · AI 19.8% | 중앙값 **14.0%** |
| 문두 접속사 (천어절당) | 사람 0.43 | 중앙값 **2.47** |

학술문은 열거가 많아 쉼표가 원래 많고 「따라서」는 논리 연결자로 정상이다.
**장르가 다르면 기준선을 새로 만든다.**

## 9. 기준선 — 파일에 있다. 여기에 수치를 적지 않는다

**같은 값을 두 곳에 두지 않는다.** 한때 기준선 수치가 `문체기준선.json`·이 문서·
스크립트 상수 세 곳에 있었고, 코퍼스를 다시 만들자 세 곳이 갈렸다.

| 무엇 | 어디 |
|---|---|
| 빈도 지표 열하나 | `docs/문체기준선.json` |
| 리듬 세 지표 | `docs/리듬기준선.json` |
| 번역체 규칙 여덟 | `docs/번역체기준선.json` |
| 어느 원고·어느 코퍼스인지 | `docs/논문설정.json` |

지금 기준선은 **현장과학교육 267편 34,028문장**(2008~2022)에서 나왔다.
받는 법은 `docs/fetch_corpus_kosss.py`. JAMS 를 쓰는 학술단체 1,606곳이 같은 API 라
학회 도메인만 바꾸면 다른 학회지도 받아진다.

**표본이 작으면 기준선이 거짓말을 한다.** 12편으로 만들었을 때 평균 문장 길이가
11.4~43.1 어절이었는데, 그중 셋이 학술지 논문이 아니었다(학위논문 둘, 교육과정 보고서).
267편에서는 14.6~33.4 다. **쉰 편은 넘겨야 한다.**

## 10. 판정은 밀도가 아니라 처방 역치로

| 항목 | 손대는 조건 |
|---|---|
| 문두 접속사 | 한 문단에 3회 이상 |
| 「이는 ~」 | 한 문단에 3회 이상 |
| **같은 기능의 종결** | 한 절에서 65% 이상이거나 5문장 연속 (11-A 절) |
| **세 항 이상 나열** | 원고 전체 문장의 15% 이상 |
| 부정 대구 | 인접한 두 문장이 모두 대구 (연쇄) |
| 「즉」 | 문서 전체 2회 이하로 |

**문서 전체를 훑어 일괄 제거하지 않는다.** 접속사 한두 개는 사람 글에도 있고
「이는 ~」은 정상적인 한국어 담화 장치다. 걷어내면 논리가 끊긴다.
부정 대구도 출현 수보다 **연쇄**가 신호다.

## 11. 문장 규칙 — 실제 한 것 먼저

> ① 실제 수행·관찰 → ② 적용 범위 → ③ 정말 필요할 때만 짧은 부정

| 고칠 꼴 | 대신 |
|---|---|
| A가 아니라 B다 | B다 |
| A를 할 것이 아니라 B를 | B를 먼저 정한다 |
| 이는 …임을 보여준다 | (관찰문을 그대로 쓴다) |
| …와 연결된다 / 맞닿아 있다 | 「…의 관점에서 보면 …」 또는 문헌을 주어로 |
| A를 넘어 B | B |
| A할 뿐 B하지 않는다 | 이 틀로 A는 할 수 있지만 B는 별도로 필요하다 |
| ~할 필요가 있다 (반복) | 한 문단에 한 번까지 |
| 명사구 여섯 개 병렬 | 「여섯 가지였다」 + 서술문 여섯 |

## 11-0. 쓰기 전에 — 번역체를 만들지 않는 세 꼴

**이 절은 검사가 아니라 집필 지침이다. 문장을 쓰기 전에 읽는다.**

번역체는 모델이 영어로 학습된 데서 온다. 다 쓴 뒤 잡는 것보다 안 쓰는 편이 싸다.
아래 셋은 **게재 논문 267편(34,028문장)에서 거의 나오지 않는다.** 그래서 한 번만
나와도 번역투로 읽힌다.

### 쓰지 않는 꼴 셋

**하나. 「~할 것은 …지다」 — 명사화 술어.** 267편에서 **0건**이다.
영어 `What this design must decide is whether to …` 의 틀이다.

> ✗ 이 설계가 **정할 것은** 어느 쪽을 줄이고 어느 쪽을 남길**지다**.
> ○ 이 설계에서는 어느 쪽을 줄이고 어느 쪽을 남길지 정한다.

> ✗ 학습자가 직접 선택하고 설명할 **부분은** 유지해야 한다.
> ○ 학습자가 직접 선택하고 설명하는 자리를 남긴다.

**둘. 개념을 주어로 세우고 범용 동사로 닫기.** 267편의 84%가 한 번도 안 쓴다.
`The scope of X is limited to Y` 를 옮기면 이 꼴이 된다.

> ✗ 그 흐름의 **적용 범위는** 현재 구현한 세 모듈에 **한정된다**.
> ○ 지금까지는 세 모듈에서만 확인하였다.

> ✗ 같은 탐구 순서를 구현한 **결과는** 검토할 출발점이 **된다**.
> ○ 같은 탐구 순서를 세 모듈에 구현하였다. 다른 모듈에서도 되는지는 앞으로 본다.

**셋. 행위를 범용 동사로 옮기기.** 267편의 96%가 안 쓴다.
`cite as` → 「~로 들었다」, `leave on screen` → 「화면에 남긴다」.

> ✗ Chinn과 Malhotra(2002)는 자료의 결함을 살피는 활동을 두 탐구를 가르는 지점으로 **들었다**.
> ○ Chinn과 Malhotra(2002)는 자료의 결함을 살피는 활동이 둘을 가른다고 **적었다**.

> ✗ EASWA는 자동화된 처리에서도 그 단서를 화면에 **남긴다**.
> ○ EASWA는 자동화한 뒤에도 분석 조건을 화면에 **표시한다**.

### 피하지 **않아도** 되는 꼴

**「A는 …하며, B는 …한다」처럼 주어 둘을 연결어미로 잇는 것.** 267편 **전부**가 쓰고
중앙값이 백 문장당 7.85회다. **정상 한국어 문형이다.**

한때 이것을 원고에서 스물다섯 자리나 찾아 가장 큰 문제로 올린 적이 있다. 게재 논문을
재기 전이었다. 피하려 들면 문장이 토막 나고 오히려 AI 쪽으로 간다.

### 방어 진술과 겹칠 때

「~할 수는 없다」 같은 부정 꼬리도 게재 논문 90%가 안 쓴다. 그런데 못 하는 주장을
막으려면 그 꼴이 편하다. **뜻을 지키고 꼴만 바꾼다** — 배제되는 대상을 이름으로
부르되 부정으로 닫지 않는다.

> ✗ 이 결과로 현직교사와 예비교사 전체의 인식을 말할 수는 없다.
> ○ 현직교사와 예비교사 전체의 인식은 이 결과의 범위 밖이다.

셋째 절(못 하는 주장)이 문체보다 위다. **꼴을 바꿀 수 없으면 부정으로 남긴다.**

## 11-A. 종결은 낱말이 아니라 기능으로 센다

**2026-09-10 에 이 지침이 한 번 틀렸다.** 위 10절이 「같은 종결어미 한 문단 4문장 연속」을
역치로 두었는데, 그 기준으로 재는 검사기가 「~하였다」 연타를 끝내 못 잡았다. 소유자가
직접 절마다 세어 표를 만들어 왔다 — *「~다 ~였다 ~다 다다다다 다로 끝나는게 한트럭인데??
이건 왜 못잡았데」*

세 가지가 겹쳤다.

1. **낱말로 셌다.** 「수행하였다」·「확인하였다」·「정리하였다」·「제시하였다」가 각각 다른
   항목으로 잡혀 「종결 206가지」가 나왔고, 그 숫자가 다양하다는 신호처럼 보였다.
   독자가 듣는 박자는 넷 다 **「연구자가 한 일을 보고하는 과거 서술」** 하나다.
2. **그 검사가 옵션 뒤에 숨어 있었다.** `--humanize` 로만 돌았다. 기본 실행에는 없었다.
3. **문단 안 연속만 봤다.** 절이 세 문장씩 여러 문단으로 나뉘면 절대 안 걸리고,
   열 문장 가운데 아홉이 과거형이어도 중간에 하나만 끼면 놓친다.

### 기능 네 묶음

| 묶음 | 꼴 | 어느 장에 몰리나 |
|---|---|---|
| **과거 보고** | ~하였다 · ~되었다 · ~았다/었다 · ~밝혔다 | 방법·결과 |
| **당위** | ~해야 한다 · ~필요하다 · ~필요가 있다 | 서론·제언 |
| **가능·난이** | ~수 있다 · ~수 없다 · ~어렵다 | 이론 |
| **현재 서술** | ~한다 · ~이다 · ~된다 · ~있다 | 이론·설계 |

**당위와 가능·난이는 한 박자로 묶어 센다.** 세는 자리는 달라도 둘 다 단정을 피하는
종결이고, 독자에게는 같은 망설임으로 들린다. 이론 장이 그렇게 읽히는 이유다.

### 방법 장이 과거형인 것은 정상이다

소유자 원문 — *「방법절이라 과거형이 많은 건 당연하지만, **과거형이 많다는 것과 문장
구조가 매번 똑같다는 건 다른 문제**야.」*

그래서 손대는 기준은 종결어가 아니라 **문장 구조**다. 아래 여덟 문장은 종결이 다 다른데도
연구일지 항목을 문장으로 바꾼 것처럼 읽힌다.

> 네 서비스를 목적 표집하였다. 교육 지향 환경은 제외하였다. 서로 다른 기능 유형이
> 포함되도록 선정하였다. 기능 유형은 … 규정하였다. 분석은 … 수행하였다. 기록 단계는 …
> 두었다. 준거로는 … 사용하였다. 분석 기준은 … 구체화하였다.

**고치는 방향은 종결 다양화가 아니라 관련 정보를 한 문장으로 합치는 것이다.**
여덟 문장짜리 체크리스트를 다섯 문장짜리 논리 문단으로 만든다. 문단당 문장 수를
15~25% 줄이는 것이 목표이고, 종결어를 억지로 바꾸면 뜻이 틀어진다.

### 나열도 같은 종류다

종결이 달라도 「A, B, C, D」가 이어지면 같은 박자로 들린다. EASWA 원고는 세 항 이상
나열이 328문장 중 59문장(18.0%)이었고 결론 한 문장이 10항이었다. 같이 센다.

## 11-B. 문체 교정 뒤에는 반드시 회귀를 대조한다

**이것이 이번 작업에서 가장 값진 절차다.** `humanize-korean` 이든 사람이든, 문체를
대규모로 고치면 **뜻이 함께 움직인다.** EASWA 원고에서 하루 93곳을 고쳤더니 양방향으로
새어 나갔다.

### 무엇이 새는가

| 방향 | EASWA 에서 실제로 | 왜 위험한가 |
|---|---|---|
| **방어가 약해진다** | 「도구의 효과로 일반화할 수는 없다」 → 「참여자가 체감한 부담에 대한 반응으로 해석하였다」 | 범위 한정으로 보이지만 **무엇이 배제되는지 이름을 안 부른다** |
| **극성이 뒤집힌다** | 「~로 볼 수는 없다」 → 「그 영향은 민감도 분석에서 별도로 확인하였다」 | 한계 진술이 **안심 진술**이 된다 |
| **주장이 세진다** | 「시사한다」 → 「해야 한다」 · 「간극이었다」 → 「핵심 문제로 확인되었다」 | 자료가 감당 못 하는 무게가 실린다 |
| **기여가 지워진다** | 초록의 「공통 탐구 흐름 위에 탐구모듈을 얹는 구조를 제시하며」 소멸 | 유령 참조 하나 지우다 명제까지 지운다 |

「일반화」라는 낱말이 원고 전체에서 **한 번**만 남았다. 그 한 번도 다른 논문을 인용하는
목록 안이었다. 표본 26명 논문에서 심사자가 가장 먼저 보는 자리다.

### 절차

1. **교정 전 판본을 반드시 남긴다.** 시각을 파일명에 박는다.
2. **`difflib` 로 절별 전후를 뽑는다.** 통째 diff 는 90KB 가 넘어 못 읽는다.
   절 제목을 붙여 원하는 절만 거른다.
3. **낱말 개수를 먼저 센다** — 「일반화」·「~할 수 없다」·「아니다」가 몇 번에서 몇 번으로
   줄었는지. 급감했으면 그 자리를 하나씩 연다.
4. **네 방향으로 판정한다** (위 표). 약화만 찾으면 세진 곳을 놓친다.
5. **옛 문장으로 통째 되돌리지 않는다.** 교정으로 좋아진 것도 있다. 지금 문장을 살리고
   **빠진 한정만 한 문장 더한다.**

### 되살리면 안 되는 것도 있다

심사가 「삭제된 기여」라고 꼽아도 되살리면 안 되는 것이 있다. EASWA 결론의 「산출값이
학습의 근거가 되는 도구에서 **일반적으로 요구되는 절차**」가 그랬다. 그 연구는 개발
방식을 비교하지도, 다른 도구를 조사하지도 않았다. **뒷받침할 수 없는 일반화**다.

> **심사 지적이라고 다 넣지 않는다. 3절(못 하는 주장)이 심사 의견보다 위다.**

## 11-C. 방법이 예고한 값이 결과에 있는지 대조한다

방법 장이 「이 문항은 각 조사의 결과에서만 다루었다」처럼 **약속**을 하면, 결과 장에 그
값이 실제로 있어야 한다. EASWA 는 표 9 주가 문항 셋을 그렇게 예고해 놓고 값을 안 실었다.

**빠진 방향이 한쪽이면 선택 보고로 읽힌다.** 그 원고는 같은 화면을 두 방향으로 물었는데
낮게 나온 역채점 문항만 싣고, 긍정 진술로 물어 평균 4.00 에 반대 0명이 나온 문항을
빼 두었다. 결론이 낮은 값 하나에만 얹혀 있었다.

기계로 잡는 법 — 방법 장에서 **「~에서 다루었다」·「~에 제시한다」·「~를 추가하였다」**가
가리키는 항목 이름을 뽑고, 그 이름이 결과 장에 나오는지 센다. 안 나오면 사람이 본다.

## 13. 검사기 규약 — 조용히 통과한 다섯 번

| 무슨 일이 있었나 | 왜 |
|---|---|
| 용어표를 0줄 읽고 「0건 통과」 | 부록 제목이 「# 부록 A」에서 「# 부록」으로 바뀌었다 |
| 캡션을 0개 읽고 「0건 통과」 | 표 번호가 「표 3-1」에서 「표 1」로 바뀌었다 |
| 본문을 다 걷은 뒤에도 대구가 남음 | 캡션을 검사 범위에서 빼 두었다 |
| 「~하였다」 연타를 넉 달 내내 못 봄 | 종결을 **낱말**로 세어 「206가지」가 나왔고, 묶어 보는 검사는 `--humanize` 옵션 뒤에 있었다 (11-A) |
| 부록 45행이 검사에 들어감 | 부록 제목이 「# 부록 A」에서 「# 부록. 서술형…」으로 바뀌었는데 **세 스크립트 가운데 하나만 안 따라왔다.** 못 찾으면 파일 끝으로 떨어지게 짜 두어 조용히 통과했다 |

다섯 다 같은 실패다 — **무엇을 몇 개 읽었는지 안 찍었다.**

**마지막 것은 원인이 하나 더 있다.** 같은 경계(부록 시작·장 제목·표 번호 꼴)를 스크립트마다
제 문자열로 찾는다. 원고 형식이 바뀌면 따라오는 놈과 안 따라오는 놈이 갈린다.
**논문마다 다른 값은 설정 파일 하나에 모으고 스크립트가 그것을 읽어야 한다.**

1. **검사기는 읽은 개수를 먼저 찍는다.** 「캡션 17개(표 12·그림 5)」처럼.
2. **0 이면 통과가 아니라 실패다.** 원고에 있어야 할 것이 0 이면 정규식을 의심한다.
3. **캡션·표 제목·주석도 검사 범위에 넣는다.** 사람이 읽는 문장이다.
4. **원고 형식(번호 체계·제목·부록 구조)을 바꾸면 검사기 정규식을 먼저 확인한다.**
5. **기계는 의심 문장을 꺼내 놓기만 한다.** 순환인지 아닌지는 사람이 그 줄을 읽고 판정한다.
6. **세는 단위가 독자가 느끼는 단위와 같은지 본다.** 낱말로 세면 다양해 보이는데 기능으로
   묶으면 한 박자인 것이 있다. 「가짓수가 많다」는 결과가 나오면 그 가짓수가 독자에게
   구별되는지 먼저 묻는다.
7. **옵션 뒤에 검사를 숨기지 않는다.** 기본 실행에 없는 검사는 없는 것과 같다.
   내가 「검사 통과」라고 보고할 때 실제로 무엇이 돌았는지 확인한다.

# Ⅴ. 에이전트 행동 규칙

이번에 사용자가 직접 고친 것들이다.

- **지어낸 문장은 표시한다.** 편집 스크립트 주석과 보고에 「이 문장은 내가 썼다」를
  남긴다. 원어민 교정·최종 확인 때 그 자리만 보면 된다.
- **내가 만든 문제는 내가 고친다.** 「어느 쪽으로 할까요」로 넘기기 전에, 그것이 내가
  넣은 오류인지 본다. 맞으면 고쳐 놓고 확인을 구한다.
- **누가 1저자인지 먼저 확인한다.** 결정을 엉뚱한 사람에게 돌리는 것은 판단을 미루는 말이다.
- **세어 보고 말한다.** 「많다/적다」를 기준 없이 말하지 않는다. 기준선이 없으면 먼저 만든다.
- **측정 도구부터 의심한다.** 이상한 값이 나오면(113어절 한 문장, 0건 통과) 원고가
  아니라 파서를 먼저 본다.
- **소유자의 지적에 무조건 동의하지 않는다.** 확인 가능한 근거로 먼저 판정한다 —
  원고 안의 실제 횟수, 규정 문서, 원문 대조. 근거를 못 찾으면 「확인 못 했다」고 말한다.
- **원고는 하나만 고친다.** 조판본을 직접 고쳐 원고에 되돌리지 않는다. 조판 산출물
  이름이 둘로 갈리면 버전 누락이 문체보다 위험하다.
- **문장은 원고 주인이 쓴다.** 에이전트는 사실 확인·제약 점검·검사를 맡는다.
  문안은 「후보」로 내고 원고에 바로 넣지 않는다.

# Ⅵ. 한 번에 다 하려 하지 않는다

EASWA 문체는 네 회차로 나눠 고쳤고 회차마다 다시 쟀다.

|---|---|---|---|

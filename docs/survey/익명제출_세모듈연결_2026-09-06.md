# 익명 제출 세 모듈 연결 기록 — 2026-09-06

## 목적

예비교사 시연에서 식현상·KMTNet 미시중력렌즈·성단 CMD 탐구 결과를 같은 익명 저장소에
남기되, 모듈별 행과 산출값을 즉시 구분할 수 있게 한다. 로그인 여부와 관계없이 앱의
브라우저 세션 UUID만 저장하며 이름·전자우편 주소 등 신원 정보는 보내지 않는다.

## 확인한 기존 결함

- 공통 탐구 화면의 익명 자동저장은 `anonSubmit`을 받은 모듈에서만 실행된다.
- 식현상 화면만 이 값을 전달했고, 성단·KMTNet 화면은 전달하지 않았다.
- 공통 저장 판단도 식현상 `fit`만 분석 결과로 인정해, 두 모듈이 산출값만 만들고 서술을
  쓰지 않은 경우에는 저장되지 않았다.
- 시트의 기존 upsert 키가 `(anon_id, target_id)`라 같은 익명 세션에서 모듈과 대상 ID가
  겹칠 경우 한 행을 서로 덮을 수 있었다.

## 반영한 데이터 계약

| 구분 | 값 |
|---|---|
| 행 식별 키 | `(anon_id, module, target_id)` |
| 모듈 값 | `exoplanet-transit` / `kmtnet` / `cluster-cmd` |
| 식현상 산출값 | 기존 `rp_rs`~`chi2_red` 열 유지 |
| KMTNet 산출값 | `derived_json`: `t0_hjd`, `u0`, `te_days`, 오차, 기준 밝기, `chi2_dof`, 자료점 수, 관측소, 추출 방식, 이벤트 유형 |
| 성단 산출값 | `derived_json`: 나이, 거리계수·거리, 소광·색초과, 금속함량, Gaia 시차 거리, 구성원 수준·수, 기준값 |
| 옛 행 호환 | `module` 빈칸은 `exoplanet-transit`으로 해석 |

`InquiryLayout`은 이제 식현상 `fit` 또는 다른 모듈의 `derived`가 생기면, 서술 입력이 없어도
분석 결과를 익명 시트에 보낸다. 서술·자가점검·Lab 응답·도구 평가는 기존 자동저장 경로를
그대로 사용한다.

  순서다. 원자료는 계속 `시트1`에만 쓴다.

실제 웹앱 URL에 같은 `anon_id=codex-module-probe-20260906`와 같은
`target_id=__module-key-probe`로 전송했다.

1. KMTNet 최초 전송 → 120행 신규 생성
2. 성단 CMD 최초 전송 → 121행 신규 생성
3. KMTNet 산출값 수정 재전송 → 120행 갱신

따라서 모듈이 다르면 행이 분리되고, 같은 모듈·대상은 자동저장 때 기존 행을 갱신한다.
`__module-key-probe`는 `score_app_records.py`의 검사 자료 제외 규칙에 따라 코호트 집계에
들어가지 않는다. 이 채점 스크립트 자체도 식현상 전용 문항 키를 사용하므로, 2026-09-06부터는
`module` 빈칸/`exoplanet-transit` 행만 집계하도록 고정했다.

전체 단위 검사에서는 기존 `validationStats.test.ts`의 클리핑 경고 문구 기대값 1건이 계속
실패했고 나머지 37건은 통과했다. 이번 익명 저장 변경의 대상 검사 14건과 빌드는 통과했다.

1. **모서리** — `border-radius` 선언 276개 중 212개를 `var(--radius-sm)`로 통일하고
   토큰 `--radius-sm/md/lg`를 모두 `0`으로. 완전 원(`50%` 27개)·알약(`999px` 35개)은 유지.

### 시연 당일 절차 — 이 순서로 할 것

1. **전날까지** 보완 작업을 끝내고 푸시한다. Render 배포는 통상 15분, 실측 최대 16분.
2. **당일 아침** 배포가 실제로 끝났는지 자산 해시로 확인한다(아래 명령). 소스 푸시만으로는 부족하다.
3. **시연 5분 전** 사이트에 한 번 접속해 무료 플랜의 대기 상태를 깨운다(첫 접속 최대 60초).
4. **시연 직후** 이 표의 `[기입]` 칸을 채운다 — 커밋 해시·시각·자산 해시·참여 규모.
   다회차이므로 **회차별 시각 범위를 모두 기록**한다. 익명 제출 로그를 코호트에 귀속시키는 근거가
   «세션 시간대»이기 때문이다(원고 3.6).
5. **첫 회차 전에 푸시를 끝내고, 마지막 회차가 끝날 때까지 `main`에 푸시하지 않는다.**
   `render.yaml`의 `autoDeployTrigger: commit` 때문에 푸시가 곧 배포이므로, 회차 사이에 푸시하면
   회차마다 다른 빌드를 본 것이 되어 «누가 어떤 빌드를 봤는지»가 깨진다.

```bash
# 당일 아침 — 배포 완료 확인 (자산 해시가 바뀌었으면 배포된 것)
curl -s https://easwa-webapp.onrender.com/ | grep -oE 'assets/[^"]*'

# 시연 후 — 그날의 배포 커밋
git log main -1 --format="%H | %ad | %s" --date=format:"%Y-%m-%d %H:%M:%S %z"
```

## ★ 2026-08-11 — 연구 설계 변경으로 **동결 원칙 폐기**

지도교수 검토 결과 연구 설계가 바뀌었고, 그에 따라 이 문서의 전제였던
「두 코호트가 동일 산출물을 검토한다」가 **더 이상 유효하지 않다.**

### 무엇이 바뀌었나

| | 이전 | 2026-08-11 이후 |
|---|---|---|
| 현직 교사 12인 조사 | 1차 반응 조사 | **현장 전문가 검토** (완료) |
| 전문가 CVI | 별도 패널 3~5인, I-CVI/S-CVI 산출 | **폐기** — 지수 산출 안 함 |
| 보완 시점 | 두 코호트 수집 **후** 일괄 | **예비교사 조사 전** |
| 예비교사 조사 | 같은 빌드 재검토 | **보완본**에 대한 재평가 |
| 두 집단 관계 | 동시 검토(수렴적 자료원) | 보완을 사이에 둔 전후 단계 |

지도교수 판단: 이미 받은 현직 교사 설문이 곧 전문가 검토다. 사람을 다시 모으기
어렵고, 교육 현장에서 쓰인다는 점에서 현직 교사가 그 판단의 주체다.

### 그래서 동결은 끝났다

**`frontend/`·`backend/` 를 지금부터 자유롭게 고친다.** 오히려 보완이 예비교사
조사보다 **먼저** 와야 설계에 맞는다. `render.yaml` 자동배포도 이제 문제가 아니다.

다만 기록 목적은 남는다 — 예비교사 조사 시점의 배포 커밋을 아래에 적어,
「현직 교사가 본 빌드」와 「예비교사가 본 빌드」가 무엇이었는지 추적 가능하게 한다.
